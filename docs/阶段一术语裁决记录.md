# 阶段一·术语裁决记录

> 依据总方针「代码即事实」：文档与代码冲突时，以当前代码实际行为为准，修正文档（不擅自改代码迁就旧文档）。
> 每条记录四要素：冲突点 / 文档说法 / 代码现状 / 裁决。
> 本记录对应 `CONTEXT.md` 阶段一第 1 步（`/domain-modeling`）的术语校准。

## D1 模块(Module) 是否含「个人资料」
- **冲突点**：`CONTEXT.md` 的「模块」只列考纲五维，未提 `PERSONAL`。
- **文档说法**：模块 = 职业理念/职业道德/教育法律法规/文化素养/基本能力。
- **代码现状**：`models.Module` 含 6 值，`PERSONAL="个人资料"`，且 `OFFICIAL_MODULES` 显式排除 `PERSONAL`；掌握度/复盘统计不计入官方五维。
- **裁决**：以代码为准。`CONTEXT` 增补 `PERSONAL` 为第六维，标注「官方模块」仅指前五维。

## D2 题型枚举缺失
- **冲突点**：`CONTEXT.md` 有「题型配比」但无题型取值清单。
- **文档说法**：仅「题型配比」概念。
- **代码现状**：`QuestionType = single/multiple/judge/blank/short`，各带明确语义（blank 归一化匹配、short 不自动判分）。
- **裁决**：以代码为准。`CONTEXT` 增补「题型」术语并列出五种取值。

## D3 出题任务分裂为单文档 / 跨文档
- **冲突点**：`CONTEXT.md` 只有笼统「出题任务」。
- **文档说法**：出题任务 = 一次资料出题异步单元。
- **代码现状**：`DocTask`（绑单文档，paper/spot 两模式）与 `KbTask`（跨多份个人资料，按 scope）两张表、两种轮询。
- **裁决**：以代码为准。`CONTEXT` 拆为「文档出题任务(DocTask)」「知识库出题任务(KbTask)」。

## D4 两套额度混为一谈
- **冲突点**：`CONTEXT.md` 只有「每日额度（作答题量）」。
- **文档说法**：每日额度按题量限速。
- **代码现状**：另有 `RealtimeUsage`（实时生成每日 3 次，变式+复盘共用，超限降级纯池化）。
- **裁决**：以代码为准。`CONTEXT` 增补「实时生成额度」并区分于作答额度。

## D5 纠错与审校未区分
- **冲突点**：`CONTEXT.md` 只有「审校」（入库前）。
- **文档说法**：审校 = 入库前检查。
- **代码现状**：`ErrorReport` 是入库后考生反馈（答案/解析/考点归属），进审校队列处理。
- **裁决**：以代码为准。`CONTEXT` 增补「纠错」并区分入库前/后。

## D6 溯源(source_chunk)未定义
- **冲突点**：`CONTEXT.md` 有「切片」但无题目级溯源概念。
- **文档说法**：切片是检索最小单位。
- **代码现状**：`Question.source_chunk` 存生成所依切片 id 清单，越界回退批级清单防幻觉。
- **裁决**：以代码为准。`CONTEXT` 增补「溯源」术语。

## D7 产品定位：泛化为通用 RAG 出题工具 —— ❌ **已撤销（2026-06-07）**
- **冲突点**：`CONTEXT.md` 标题/导语称「教资《综合素质》方向」，但其「知识库」定义已写「出题不再限定于教资范畴」，代码 `Module.PERSONAL` 也支持任意领域资料出题。
- **两种说法**：A) 仍定位教资刷题工具；B) 泛化为「任意资料→出题」通用 RAG 工具；C) 两者并存分轨。
- **原裁决（用户 2026-03-29）**：采用 B) 泛化。
- **⚠️ 撤销裁决（用户 2026-06-07）**：**撤销 B)，改回 A) 垂直锁定 NTCE 教资备考。**
- **撤销理由**（依据《中小学教师资格考试(NTCE)备考指南》校准，详见 `docs/用户需求文档.md` v2.0 §5 D7）：
  1. 「代码能跨领域」不等于「用户需要跨领域」——泛化的依据是**技术能力**而非**用户需求**，属本末倒置。
  2. 备考用户的核心材料是**官方考纲 + 历年真题**（指南 §7 原文），而真题因版权不能入库，
     因此「上传任意资料出题」并非备考主场景，把它做成主线直接偏离了用户目标。
  3. 泛化后产品失去可校验锚点：非教资资料的正确性**无法校验**，
     而「考试有标准答案、可对照考纲校验」恰是本产品质量的唯一依据（见 `需求分析文档.md` 1.2）。
- **落地**：
  - `docs/用户需求文档.md` v2.0 为**现行权威需求口径**，与本条冲突的旧表述一律失效。
  - 「上传资料出题」**降级**为次要能力（偏差 D5）；`Module.PERSONAL` 作为能力保留但不作为定位主线。
  - 下方 C4 裁决（基于 D7 泛化推导）**同步撤销**。
