# 提交历史

> 「提交记录」表由 `git log` 同步生成，**覆盖全部提交**；「详细记录」为部分提交的人工补充（范围见该节说明）。
> **权威记录以 `git log` 为准**，本文件是人工可读的索引，每次提交后同步更新。
> 时间均为本机时区。

## 查看方式

```bash
git --no-pager log --oneline              # 全部提交（一行一条）
git show <hash>                            # 某次提交改了什么
git log --follow -p -- <文件路径>          # 某个文件的完整演变
git log --graph --oneline --all            # 图形化分支历史
git log --pretty=format:"%h|%ad|%s" --date=format:"%Y-%m-%d %H:%M:%S"   # 带时间的简洁列表
```

## 提交规范

格式：`<类型>(<范围>): <一句话描述>（#票号）`，正文另起一段写「为什么」。

- **范围（scope）只写模块名，不写票号**：`mp`（小程序）/ `kb`（知识库）/ `chat`（AI 模拟答）/
  `doc`（上传资料）/ `review`（复盘）/ `sessions`（闯关判分）/ `admin`（审校后台）/ `cleanup`（仓库整理）
- **票号**指 `.scratch/<feature>/issues/NN-<slug>.md`；没有工单可省略
- 多要点用「——」分隔；正文写「为什么这么改 / 取舍 / 怎么验证」，不重复 diff 已能看出的「改了什么」

| 类型 | 用途 |
| --- | --- |
| `feat` | 新功能 |
| `fix` | 缺陷修复 |
| `docs` | 文档 |
| `chore` | 工程配置、依赖、仓库约定 |
| `refactor` | 重构（不改变外部行为） |
| `test` | 测试 |
| `style` | 格式（不改语义） |
| `perf` | 性能 |

模板见仓库根 `.gitmessage`，启用一次即可（本地配置，不随仓库走）：
`git config commit.template .gitmessage`
