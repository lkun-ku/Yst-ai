## 0. 30 秒项目介绍（开场必背）

> 这是一个**微信原生小程序 + FastAPI** 的 AI 学习产品，面向教资《综合素质》备考。核心是三条学习链路：官方题库闯关、用户上传资料的**跨文档 RAG 出题**、以及**AI 模拟答**（聊天式追问评分训练）。
>
> 技术上最有代表性的三点：
> 1. **LLM 接缝设计**——所有 AI 调用收口到一个 `LLMClient` 接口，Fake/Real 同接口，使全链路测试零额度；
> 2. **RAG 出题的工程质量闭环**——三级检索降级、规则校验前置、判重、补偿轮保证不欠产、溯源防幻觉；
> 3. **AI 模拟答的对话状态机**——追问式评分、补充轮次上限、离题出口、会话恢复。

个人贡献（按此口径准备）：主导了 AI 模拟答模块从 0 到 1（后端评分链 + 前端聊天交互）、离线题库生成管线（418 题真实题库替换占位假题）、以及一批交互级 bug 的根因修复。

## 1. 架构与设计类考点

### 1.1 整体分层与职责划分 ★★★★★

**可能问**：介绍一下系统架构？为什么这么分层？前后端如何通信？

**考察点**：分层清晰度和「为什么」，不是背诵目录。

**回答要点**：
- 四层：表现层（小程序）/ 接口层（FastAPI Router）/ 服务层（不依赖 HTTP 的业务逻辑）/ 数据层（Models + Alembic）。
- **服务层不依赖 HTTP** 是刻意的：出题、判分、连胜等逻辑可被单测与离线脚本直接调用（如 `batch_generate` 既服务闲时扩池，也可命令行跑）。
- 通信：REST/JSON + `X-Unionid` 头识别身份；无 JWT（小程序内部信任域），admin 用独立 Token。
- 前端无状态管理库，用 `globalData.session` 传递当前闯关局（小程序页面栈场景足够，避免引入复杂度）。

**追问**：为什么不用 tabBar？——全站是「首页为唯一枢纽」的树形导航，符合单任务流产品形态。

### 1.2 LLM 接缝设计（可测试性）★★★★★

**可能问**：AI 模块怎么做到可测试？怎么切换模型供应商？

**考察点**：依赖倒置、可测试性设计——这是 AI 工程最常考的点。

**回答要点**：
- `services/llm_client.py` 定义 `LLMClient` 抽象基类，`get_llm_client()` 是**唯一切换点**（`LLM_MODE=fake|real`）。
- `FakeLLMClient` 为每种 `kind`（variant / doc_question / chat_pack / chat_grade / review_paragraph）返回**确定性产物**；例如 `_fake_doc_questions` 用全局自增下标保证伪题不重复，避免被判重逻辑误杀。
- 收益：全链路测试零 API 额度、零网络抖动，CI 可跑。
- 切换供应商只改 `LLM_API_BASE/KEY/MODEL`（OpenAI 兼容协议），实测 DeepSeek 与通义都直接可用。

### 1.3 Fail-open 与 Fail-close 的取舍 ★★★★★

**可能问**：AI 调用失败时怎么处理？都会降级吗？

**考察点**：是否有「边界意识」，能否区分「能降级」与「不能降级」。

**回答要点**（表格化，很有说服力）：

| 场景 | 策略 | 理由 |
|---|---|---|
| 评分/判分失败 | **Fail-close**：报错、不落数据 | 静默给分会污染数据并误导用户 |
| 内容安全检测 | **Fail-close**：不通过即换占位 | 合规硬要求 |
| Embedding 失败 | **Fail-open**：标记后继续 | 不阻塞上传，检索可降级 |
| LLM 自检不可用 | **Fail-open**：保留规则通过项 | 自检不得成为欠产原因 |
| 检索为空 | **Fail-open**：向量→关键词→均匀采样 | 宁可质量下降也不能出不了题 |
| 过程事件写入失败 | 静默回滚，但**取消信号必须传播** | 过程数据可丢，用户指令不可丢 |

### 1.4 数据模型的关键设计 ★★★★

**可能问**：题目表怎么区分官方题和个人题？如何防止越权看到别人的题？

**回答要点**：
- `Question.owner_candidate_id`：**NULL = 官方池人人可用；非 NULL = 个人题仅本人可见**。抽题时一条 SQL `(owner IS NULL) OR (owner == c.id)` 同时完成「可见性 + 隔离 + 越权防护」。
- `Module.PERSONAL` 与 `OFFICIAL_MODULES` 常量分离：任何官方统计（雷达/掌握度/薄弱排序/额度）都遍历 `OFFICIAL_MODULES`，**绝不遍历 `Module`**，防止个人题串入官方统计。
- `Sessions.result_json` 兼作**交卷幂等缓存**：重复提交返回同一结果，避免掌握度重复累加。

**追问**：为什么个人题不计入每日额度？——B3 决策：用户自己的资料出题，不消耗平台供给。

## 2. RAG 与 AI 工程类考点

### 2.1 检索链路与三级降级 ★★★★★

**可能问**：RAG 检索怎么做的？向量库不可用怎么办？

**回答要点**：
- 切分：`clean_text()` 去页眉页脚/页码/合并断行 → 按标题切段 + 滑窗（size 1500 / overlap 200）。
- 双库分发：PG 用 `1 - (embedding <=> CAST(:q AS vector))` 走 HNSW；SQLite/dev 用内存 numpy 余弦。
  - 💡 细节加分：必须写 `CAST(:q AS vector)` 而不是 `:q::vector`，因为 SQLAlchemy 会把 `::` 当转义符。
- 跨文档用 **RRF 融合**（k=60）+ `heading_bonus`（章节标题命中加权，上限 0.5）。
- **三级降级**：向量 → 关键词（中文二元组）→ 均匀采样。任何一级都不让出题流程中断。

### 2.2 出题不欠产的工程手段 ★★★★★

**可能问**：模型经常少输出题，怎么保证用户要 10 题就给 10 题？

**考察点**：真实工程经验（这是最体现实战深度的点之一）。

**回答要点**（四层保障）：
1. **小批次**：`doc_batch_size=3`（从 6 下调——实测一次要 6 题模型常只输出 3 题）。
2. **多生成候选再截断**：补偿轮 `want = min(batch*2, max(need*2, 2))`，落库按 `limit=need` 截断（不超产且提高命中率），最多 6 轮。
3. **放宽判重阈值**：仍不足时阈值从 0.6 放到 0.95 再补一轮——宁可题干略相近也不欠产。
4. **降粒度重试**：`3→2→1`（`n=(n+1)//2` 向上取整）。

补充：**章节配额用最大余数法**（先均分，余数按段长降序补给最长的段）——曾踩坑：各题型各自 `round()` 会让每段都算成 0，导致整卷 0 题。

### 2.3 判重与溯源（防幻觉）★★★★

**可能问**：AI 生成的题重复怎么办？怎么知道一道题依据的是哪段原文？

**回答要点**：
- **判重两层**：精确层用 `normalize_stem()` 归一化后命中集合即弃；近似层用**字符 3-gram Jaccard** 与最近 300 条题干比对。
- **阈值分场景**：章节配额下题干模板天然相似，用 0.85；跨文档用 0.6；`fake` 模式整体跳过（伪题相似度约 0.8 会误杀）——这个细节说明阈值是实测调出来的。
- **溯源防幻觉**：优先用模型回传的 `source_id`，但**必须落在本次召回切片 id 集合内**才采信，否则回退批级 `source_chunk`（id 清单）。避免模型编造不存在的切片。

### 2.4 质量闭环：规则校验 + 自检 + 人工抽检 ★★★★

**可能问**：怎么保证 AI 出的题是对的？

**回答要点**（三层闸门）：
1. **机器校验（前置必过）**：按题型的字段/选项/答案规则，不通过即弃。这是所有 AI 产物的第一道闸。
2. **LLM 自检（可选）**：抽检优先（`sample=2`，均匀取样覆盖首尾），发现问题才升级全批检；自检全否时**仍保留规则通过项**——自检不得成为欠产原因。
3. **人工抽检**：按模块比例（文化素养 0.3、其余 0.1），REJECTED = 驳回即弃（直接出池）。
4. 入库后还有**纠错工单**（答案/解析/考点归属）回流审校队列。

### 2.5 离线题库管线（断点续跑 + 网络加固）★★★★

**可能问**：批量生成题库时崩溃了怎么办？

**回答要点**：
- 每考点完成即**实时落盘** JSON，崩溃不丢进度。
- 重跑按已完成考点集合排除 → **断点续跑**。
- 曾因 LLM 连接超时（WinError 10060）未捕获导致整条挂机管线崩溃 → 补了：调用层 2/4/8s 指数退避重试 ×3；**考点级兜底**——重试耗尽只跳过该考点记 0 题继续。
- 成果：418 题、150 考点 100% 覆盖、REJECT 率 12%（熔断线 30%），替换了 300 条占位假题。

### 2.6 AI 模拟答：对话状态机与评分链 ★★★★★

**可能问**：AI 模拟答怎么实现「像真面试官」？怎么防止对话死循环？

**回答要点**：
- **纯 LLM 生成路线**：不再从题库包装（包装题带「选择题腔」），改为现场生成情境化面试题 + 3-4 个评分要点，并用 `avoid`（已问话题）防重复。
- **评分三态**：`off_topic`（提示）/ `need_probe`（追问）/ `final`（终评按要点覆盖率给分）。
- **防死循环**：**提示与追问共享补充轮次上限 2**，达上限强制终评——这是修出来的：早期提示不计次数，用户反复套用旧答案会永远收提示、拿不到分。
- **绝不 fail-open**：评分失败 503 且不落任何 turn，本题状态不变可重试。
- **真人感靠提示词纪律**：禁止试卷腔；追问必须**引用用户原话**再发问；触及 ≥1 个要点就必须直接评分（不为难用户）。

## 3. 后端实现类考点

### 3.1 抽题与组卷算法 ★★★★

- **避免相邻同题型**：shuffle 取前 n 后单趟扫描，相邻同题型则从后方找第一个不同题型交换。
- **模考权重抽题**：按卷面权重（基本能力 48 最高）逐模块 `max(1, round(n*w/100))`，不足从全池补齐再 shuffle。
- **量不足降级而非 409**：按实际数量开局，额度按实际题数校验（修复过重练必然 409 的 bug）。

### 3.2 判分与统计口径 ★★★★

- 多选**四态**（correct_selected / missed / wrong_selected / wrong_not_selected），前端据此区分「漏选」与「选错」。
- 填空归一化（全角转半角、去空白、去句末标点、小写）后集合匹配。
- 简答 `self_review`：**不计掌握度、不进错题本、不计正确率分母**——避免主观题污染客观统计。
- 掌握度 **EMA**：`score = score*0.7 + correct*0.3`（α=0.3）。

### 3.3 时区与「本地日」★★★

**可能问**：每日额度/连胜按天统计，怎么处理时区？

**回答要点**：SQLite 存储是 UTC，直接用 SQL 日期函数会比较错。统一到 **Python 侧按服务器本地时区比对**（`created_at.astimezone().date() == local_day()`），`utils.local_day()` 作为唯一入口，避免各模块各写一套。

### 3.4 并发与异步任务 ★★★★

- 后台任务**独立 Session**（A6），`_cancelled` 检查**不能 rollback**（否则丢掉未提交的已生成题）。
- **GEN/EMBED 分池**：出题 worker 会等 embedding，共用有界池会死锁——这是正确性要求，不是性能优化。
- 协作式取消：`should_stop()` 只在批次间生效，已出题作为**部分卷**保留。

### 3.5 幂等设计 ★★★★

交卷（result_json 缓存）、补签（唯一约束 candidate_id+missed_date）、连胜推进（同日不重复）、种子导入（三元组去重）——**凡是可能被重试或重复点击的操作都做了幂等**。

### 3.6 配额与限流 ★★★

- 两套独立限速：**每日额度**（作答题量，超限 429 友好提示不强制付费）与**实时生成额度**（LLM 调用，每日 3 次，超限降级池化无感）。
- 池化率告警：实时占比 >5% 告警，用于监控成本漂移。

## 4. 前端实现类考点

### 4.1 请求层四大机制 ★★★★

**可能问**：小程序网络层怎么封装的？

**回答要点**（`utils/api.js`）：
1. **在途请求去重锁**：`inflight` Map，key 用**递归排序序列化** `stableStringify`（修正过 D8：`JSON.stringify` 键序敏感会漏判）。可 `lock:false` 关闭（轮询/增量拉用）。
2. **计数式全局 loading**：只在 0→1 / 1→0 时开关导航栏 loading，避免并发闪烁。
3. **游客身份注入**：每个请求前 `ensureIdentity()`，并发复用同一 Promise。
4. **GET 网络失败自动重试一次**（非 GET 不重试，避免重复建会话）。

错误统一走 `errClassify`（401/409/410/429/网络/服务端分类）→ `toastApiError`；跳转统一 `navTo/redirectNav/reLaunchNav`，失败必须 toast 不静默。

### 4.2 性能：渲染态与非渲染态分离 ★★★★

**可能问**：答题页题目很多（含长解析），怎么避免卡顿？

**回答要点**：answer 页把 `_questions/_answers/_revealed/_curIdx` 挂在 **this 实例（非 data）**，`_render()` 只把**当前题**的视图模型送进 setData（预计算好每个选项的 class、标记、进度）。避免每答一题就把整套题（含长解析）序列化一遍——这是小程序 setData 性能的核心原则。

### 4.3 交互细节与踩坑 ★★★★★（最体现 debug 能力）

| 现象 | 根因 | 解法 |
|---|---|---|
| 聊天滚不到底 | 父级 `min-height:100vh` → flex 子项按内容撑开，scroll-view **不产生内部滚动**，底部被输入栏遮住 | 父级 `height:100vh` + `min-height:0` + 底部留白 |
| `scroll-into-view` 无效 | 锚点 id 双前缀；同值不触发重滚 | 固定双锚点 a/b 交替 |
| 一次回答两条气泡 | `onSend` push + `_reply` 默认 `local=true` 再 push | 统一由 `_reply` push |
| 答一轮后发送失效 | 防连点条件引用未赋值字段，恒真 | 实例同步锁 `this._sending` |
| 白屏 `module "app.js" is not defined` | `es6:false` 关闭 ES6 转 ES5，而源码全是 ESM | 开启转换 |
| 连点出现两条消息 | setData 异步，data 检查挡不住连点 | 同上同步锁 |

**答题话术**：这类问题的共同特点是「现象在 UI 层，根因在数据/布局/时序层」，我的方法是**先复现 → 定位到具体行 → 改根因而非症状**。

### 4.4 打字机与流式体验 ★★★

- 后端同步返回 + 前端逐字渲染（`setInterval` 30ms/2 字 + 光标 `▍`），成本极低体验足够。
- 出题时间线同理（`_tick()` 队列驱动 + 递归 setTimeout），并按 `seq` 更新同一条 phase（同章节连续出题不刷屏）。
- 升级方向：改 SSE/分块流式降低首字延迟。

### 4.5 图标与 UI 规范 ★★★

- 图标用 **Reicon → data-URI SVG（base64）**，`<image>` 渲染：零 npm 依赖、不依赖网络、可任意换色。
- 全站**零 emoji**（规范 3.D），头像用文字圆标（AI / 我）。
- 设计令牌集中在 `app.wxss`（颜色/圆角/间距/字号），改版按「纸卷 v1」渐进替换。

## 5. 工程与协作类考点

### 5.1 测试策略 ★★★★

- 后端 27 个测试文件约 250 用例；`conftest.py` 用独立 `.test_tmp.db` 做 session 级重建。
- **测试不强制 fake**：真实模型下出题/判分才可信（代价是慢）；但对 chat 这类新模块改用**依赖覆写注入 fake**，保证零额度且真覆盖逻辑。
- 前端用 vitest 只测 `utils/` 纯逻辑（小程序运行时零依赖）。
- 另有 HTTP 冒烟脚本、UAT 走查脚本、`eval/` 效果评测（LLM-as-judge 五维 rubric）。

### 5.2 数据库双库兼容 ★★★

- `embedding` 列用 `with_variant(PgVector(1024), "sqlite")` → 同一模型定义，PG 是 `VECTOR(1024)`、SQLite 是 `LargeBinary`。
- dev/test 用 `create_all`，生产用 Alembic（13 个迁移版本）。
- 检索层按 dialect 分发。

### 5.3 零表迁移的功能演进 ★★★

纯 LLM 路线需要随题存要点，但表已存在且 `create_all` 不 ALTER → **复用 ask 轮的 `points_hit` 列**存 key_points，配注释守住约定。
（加分：说明这是权衡——避免迁移成本，代价是需要注释与测试保护约定。）

## 6. 高频追问与「陷阱题」预判

| 追问 | 考察意图 | 应答要点 |
|---|---|---|
| 「为什么不直接用 LangChain / LlamaIndex？」 | 技术选型的自主判断 | 路线③确实用 LangGraph 做过对照实验；核心链路手写是为了**可控**（欠产补偿、判重阈值、溯源校验这些业务规则，框架抽象反而碍事）。详见 `docs/RAG路线三落地复盘.md` |
| 「AI 出的题错了怎么办？」 | 质量闭环意识 | 三层闸门 + 纠错工单回流 + REJECTED 出池；且坚持「不存储原题原文」的合规边界 |
| 「实时生成太贵/太慢怎么办？」 | 成本意识 | 两套额度隔离；池化率告警；离线管线预生成（418 题）；超限降级池化用户无感 |
| 「为什么不用 JWT？」 | 安全理解 | 小程序信任域 + unionid 头；admin 独立 Token。若要上生产会补签名校验与 HTTPS 强制 |
| 「多用户数据怎么隔离？」 | 安全意识 | `owner_candidate_id` + 每个接口 `get_current_candidate` 鉴权 + 抽题 SQL 内建隔离；删除接口级联清回合 |
| 「项目最大的技术难点？」 | 总结能力 | 建议答：**在 LLM 不确定性之上构建确定性**——用接缝、闸门、补偿、降级、幂等五类手段把不可控变成可控 |
| 「你个人做了什么？」 | 贡献真实性 | 见第 0 节的个人贡献口径，并能展开每个模块的决策理由 |

## 7. 项目亮点一句话清单（收尾用）

1. **LLM 接缝 + Fake 实现**：全链路测试零额度，模型可替换。
2. **RAG 出题不欠产工程**：小批次 + 多候选截断 + 阈值放宽 + 降粒度重试 + 最大余数法配额。
3. **溯源防幻觉**：模型回传的切片 id 必须落在召回集合内才采信。
4. **Fail-open / Fail-close 分级**：知道什么时候能降级、什么时候必须报错。
5. **离线题库管线**：断点续跑 + 网络加固，418 题替换占位数据。
6. **AI 模拟答对话状态机**：追问式评分 + 轮次上限 + 离题出口 + 会话恢复。
7. **交互级 bug 的根因修复**：滚动布局、双气泡、发送锁、ES6 转译——都能说清根因与解法。
