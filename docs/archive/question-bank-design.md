# 官方题库架构设计（题源与生成管线）

> Status: 已确认（用户逐项决策）。来源：grilling 设计访谈（2026-03-04）。
> 关联：spec.md 决策 12~17（题目供给）、issue #04（seed 导入）。

## 问题

官方池现状：150 考点（5 模块 x 30）全覆盖，但题目是模板占位假题（「关于《XX》的正确表述（种子变式1）」），无法支撑真实备考。

## 决策记录

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | 题源 | 无真题，全 LLM 生成 | 用户确认无真题数据；真实范围由教资考纲 + 150 考点体系保证 |
| D2 | 考点归属 | 生成时直接按考点出题 | 按 150 考点逐个生成，天然对齐 |
| D3 | 题型 | 全单选 | 教资综合素质客观题卷面只有单选（29 题），贴近真实 |
| D4 | 题量 | 每考点 3 题 = 450 题 | 深度够刷；成本可控 |
| D5 | 生成模型 | deepseek-flash | 已切换 |
| D6 | 审校 | 生成 - 批量 judge - REJECTED 重生成一轮 - PASSED 落盘；全自动，人工只抽查 | 唯一用户场景抽人工无意义，纠错入口兜底 |
| D7 | 持久化 | 双层：SQLite 运行时 + JSON 资产入 git | 数据即代码，题库永不丢失 |
| D8 | 抽题 | 同池等概率，解析页标注来源 | AI 题审校后质量对等；权重随时可调 |
| D9 | 占位题 | 清空替换（import clear=True） | 假题污染抽题体验 |
| D10 | 执行 | 分批脚本 + 断点续跑 + 进度落盘 | 150 次调用挂机 30~60 分钟，中断可续 |

## 管线

KNOWLEDGE_POINTS(150 考点) -> 生成（deepseek-flash，每考点 3 题，严格 rubric）-> 批量 judge（每 10 题一批：答案正确性/干扰项合理性/考点归属，REJECT 即弃）-> REJECTED 重生成一轮 -> 全量 PASSED 落 backend/app/seed/real_questions.json（分段落盘，可断点续跑）-> 人工抽查 -> import_questions(clear=True) 清空占位入库。

## 质量红线

- 答案必须唯一且正确；干扰项不得明显荒谬；题干不得出现「关于《XX》」模板句
- REJECTED 率 > 30% 时暂停管线人工介入
- 每考点最终不足 2 题时记录缺口（先上线，缺口后补）
