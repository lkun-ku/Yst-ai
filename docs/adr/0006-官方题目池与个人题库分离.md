# 题目归属：官方题目池与个人题库严格分离

## Status

accepted（2026-03-22）

## Context

引入「资料出题」后，题目有两类来源：

1. **官方题**：以考纲/考点骨架生成的变式题，进入题目池，经结构化校验与人工抽检。
2. **个人题**：用户上传资料生成的题，不进官方池、**不经人工审校**，质量与版权责任由用户自负。

若混用会带来两个风险：

- 未经审校的个人题污染官方题库，直接违反 R1「AI 生成错误题目误导考生」的缓解措施。
- 个人题的考点不在官方考纲骨架内，会污染五维掌握度雷达与薄弱考点统计。

## Decision

用 `owner_candidate_id`（NULL = 官方）+ `source`（`pool` / `doc`）+ `doc_id` 三个字段把两类题目**严格隔离在同一张 `questions` 表内**，不建第二张题表。

## Considered Options

- **建第二张个人题表**（放弃）：答题、判定、复盘、错题本、历史全部要写两套实现，成本高且易不一致。
- **单表 + 归属字段**（采用）：公共逻辑默认只取官方题，个人题库走独立的 `doc_id` 入参分支。
- **复用同表但不隔离**（放弃）：质量与统计污染，直接违反 R1。

## Consequences

- **个人题永不进入官方题目池**——错误题目被结构性隔离在上传者自己的库里。这是对 R1 的架构级缓解，比「人工抽检」更适配「用户自主上传、产品侧不审校」的场景。
- 个人题以 `Module.PERSONAL`（个人资料）独立成维，官方五维雷达不受影响（复盘接口显式排除 PERSONAL）。
- 个人题库闯关**不消耗每日额度**（题目已生成，边际成本为零），额度统计排除 PERSONAL 维度的闯关局。
- 删除资料时**级联移除**其生成的个人题（`doc_id` 外键）。
- 简答题等无法机器判分的题型标记 `self_review`，不计入正确率分母、不进错题本。
