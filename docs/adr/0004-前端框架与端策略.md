# 前端框架与端策略：Taro 4 + Vue 3，只做微信单端

技术栈沿用 Taro 4 + Python FastAPI，但把官方器方案中的 React 换成开发者更熟悉的 Vue 3。Taro 官方器定位为「支持 React/Vue 的开放式跨端跨框架解决方案」，Taro 4 + Vue 3 + TypeScript + NutUI + Pinia 是可用的成熟组合；但 Taro 源自 React 生态，Vue 3 在其中的教程、模板与踩坑记录明显少于 React，且多端适配存在已知边角问题（社区有 Vue 3 项目在非微信端异常的反馈）。因此我们决定：**采用 Vue 3，但只承诺微信单端，不对外承诺多端**。

## Status

accepted（2026-05-21）

## Considered Options

- **跟随官方器方案用 React 18**（放弃）：生态与资料最全，但开发者熟练度低，会拖慢工期。
- **微信原生 + Vue 风格**（放弃）：无跨端可能，且生态工具链弱于 Taro。
- **uni-app + Vue 3**（未采纳）：Vue 支持更原生，但会与已确定的 FastAPI 后端方案及官方器教程路径割裂，且同样有多端适配成本。

## Consequences

- 产品定位为**微信小程序单端**。任何「顺便支持 H5 / 支付宝 / 抖音」的需求都应被拒绝，除非明确追加工期与适配测试预算。
- 组件库选择 NutUI（京东，Vue 3 支持良好）；不引入需要 React 运行时的组件库。
- 遇到 Taro + Vue 3 的框架级问题时，可参考的中文资料较少，优先查 Taro 官方器仓库 issue 与 Vue 3 相关实践，而非 React 教程。
- 后端为 Python/FastAPI，与前端框架选择完全解耦，不受本决策影响。
