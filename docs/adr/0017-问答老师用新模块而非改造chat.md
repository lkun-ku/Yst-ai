# 问答老师：新建 `teacher_agent` 而非改造 `chat.py`；拒答由证据决定而非轮次

## Status

accepted（2026-06-11）

> 上游：[ADR-0009](./0009-知识库出题编排框架引入裁决.md)（LangGraph 引入）、
> [ADR-0014](./0014-引用校验用子串硬匹配.md)（引用硬校验，本项直接复用）、
> [ADR-0013](./0013-官方语料命名空间隔离.md)（工具不得越过权限边界）。
> 范围依据：`docs/改造计划.md` §3 第 7 项。

## Context

计划里第 7 项写的是「**改造 `chat.py`** 为有据答疑（保留无据版作对照）」。
真正读完全文之后，这个前提不成立：

`chat.py` 是一个**完整的面试训练闭环** —— 面试官出情境题 → 考生用自然语言答 →
追问链（≤2 轮）→ 终评给分落库 → 历史/趋势统计 → 语音输入输出。
它训练的是**"答"**；而"有据答疑"解决的是**"问"**（考生问，老师答）。

把它改造过去，是**替换**这个功能，而不是增强它。

另外计划里的两条要求本身是对的、必须满足：
① 「保留无据版作对照」；② 「度量引用首次通过率与拒答率区间」。

## Decision

### 1. 新建 `teacher_agent` / `tools` / `prompts_teacher` + `routers/teacher.py`；`chat.py` 一字未动

| 模块 | 方向 | 解决什么 |
| --- | --- | --- |
| `chat.py`（不变） | 面试官提问 → 考生回答 → 追问 + 评分 | 训练"答" |
| `routers/teacher.py`（新） | 考生提问 → 检索考纲/法条 → 带引用作答 | 解决"问" |

**"保留无据版作对照"改为做成模式**（`mode="plain"`），而不是留一个旧端点。
理由：对照实验要控制变量 —— **同一套提示词、同一个接缝、同一个引用校验，
唯一差异是有没有检索**。留旧端点会把"模型换代""提示词漂移"一起混进差异里。

### 2. 三档能力阶梯（同一张图，靠 `mode` 路由）

| mode | 做什么 | 用来回答什么 |
| --- | --- | --- |
| `plain` | 不检索直接作答 | 无据版对照 |
| `grounded` | 检索一次 → 带引用作答 | 基础 RAG QA |
| `agent` | 模型自主决定 检索 / 查条文 / 自检（循环） | 多跳问题 |

### 3. 三个工具，其中 `lookup_law` 是本项最重要的设计

| 工具 | 解决什么 |
| --- | --- |
| `search_kb` | 宽召回（向量 ⊕ 关键词 → RRF，含精排） |
| `lookup_law` | **按「法名 + 条号」结构化取条文** |
| `check_quote` | 校验一段引用是否真在库里（让模型主动自检） |

`lookup_law` 是 ADR-0015/0016 里那个结构事实的**收口**：
法名与条号只出现在 `heading_path` 里，因此「《教师法》第七条」这类问题
**向量与 BM25 都做不可靠** —— 而它本质是**结构化查询**。
把它做成工具交给模型，比让它反复改写检索词去碰运气可靠得多。

**顺带堵住一个"编造条文"的入口**：`LIKE %第七条%` 会命中「第七十七条」，
所以 SQL 粗筛之后**必须在应用层复核条号段是否精确相等**；
复核全灭时**如实返回空**，而不是把模糊命中当答案。
（这条由 `test_不把第七十七条当成第七条` 钉住。）

### 4. 工具决策用「结构化文本契约」，不用原生 function calling

原生 `tools=[...]` 更省一次解析，但 ① 本仓 `LLMClient` 是**纯文本接缝**，不是 `BaseChatModel`；
② 原生工具调用**无法离线测试**（`LLM_MODE=fake` 下没有真实供应商），
必然成为又一条"只能标注未验证"的分支。文本契约任何模型都能用，
且 Fake 实现能给出确定性决策，链路可端到端离线测试。

### 5. 拒答的判据**刻意偏离**计划流程图

计划图写「超限或仍不足 → REFUSE」。实现里拒答**只看证据**，不看轮次：

- 超限但**有**材料 → 作答（引用校验会拦住编造）。拒答会让用户白等几轮然后一无所获；
- 未超限但**没**材料 → 拒答。继续循环只是多烧几次调用去确认「查不到」。

并且 **sufficiency 由证据算，不由模型自称**：模型说"够了"只用来**结束循环**，
不用来**决定能不能答** —— 否则模型一句"我确定"就能绕过拒答。

### 6. 引用校验是硬的，且放在最后

`verify` 节点复用 `citation.verify_payloads`（与出题链路**同一个判定**）。
只要有一条引用无法在观察到的材料里定位，整条回答转拒答 ——
"句句有出处"是产品承诺，带一条编造依据的回答不能因为"其余都对"而放出去。

## Considered Options

- **改造 `chat.py`**（否决）：会替换掉一个完整的面试训练功能。
- **同时保留 `chat.py` 作为无据版对照**（否决）：两份代码会漂移，差异不可归因。
- **原生 function calling**（暂缓）：不可离线测试，会再添一条未验证分支。
- **拒答由轮次触发**（否决）：用户白等几轮后一无所获。
- **sufficiency 采信模型自称**（否决）：那等于把拒答开关交给被检查方。
- **引用校验失败时只降置信度、照常输出**（否决）：带编造依据的输出不该放出去。
- **只数"有没有材料"就算有据**（**实测否决**）：检索永远返回 top-k，该判据几乎恒真 ——
  实测正确拒答率为 **0**（见下）。

## Consequences

- **产品多了一条"问"的入口**，且它与出题链路共用同一套检索、引用校验、命名空间隔离 ——
  没有第二套实现，也就没有第二套漂移。
- **基准**（`eval/teacher_eval.py`，25 问，`LLM=fake`，`RERANK_IMPL=off`）：

  | 模式 | 引用首次通过率 | 误拒率 | 正确拒答率 | 工具调用均值 |
  | --- | --- | --- | --- | --- |
  | grounded | 1.0 | 0.0 | **0.0** | 1.0 |
  | agent | 1.0 | 0.0 | **0.0** | 1.0 |
  | plain | 0.0 | 0.0 | **0.0** | 0.0 |

- **`正确处理拒答率 = 0` 是本次最有价值的发现**：它说明"有据"的判据太弱。
  为此补了一道**相关性下限闸门**（检索来的切片必须有关键词命中或精排正分；
  结构化定位来的切片直接算精确证据）。

### 已知边界（记为未决，不假装已完成）

1. **相关性下限只挡住了"与库完全无词形重合"的一类**
   （问量子物理而库里只有教育法条）。它**挡不住**「像真的但库里没有」的一类
   （问《民法典》而库里只有教育法条）—— 这类问法与库共享大量常用字组
   （「第一」「六十」「十条」「怎么」「规定」），词形下限判不出来。
   **而它恰恰最危险**：模型会自信地引一条不相关的法条作答。
   语义级判定应复用 `kb_generate._grade_and_filter` 的相关性评分，**本项未做**。
2. **`LLM=fake` 下这张基准只证明"链路通、判据生效"**，不是"真实模型下答得准"的证据。
   真实模型下必须重跑（`LLM_MODE=real`），届时拒答率与引用通过率都会变化。
3. **`Scope.subject` / `stage` 仍不参与 SQL 过滤**（ADR-0013 已记录），
   所以"按科目问"暂时只在语义上成立。
4. **前端未接**：本次只做了后端接口与度量，小程序页面（计划里的 `pages/teacher/`）未做。

## 反转条件

1. **若引入语义相关性判定**后正确拒答率明显上升，说明词形下限确实只是权宜之计，
   应把它降级为"快速前置过滤"而由语义判定做主。
2. **若原生 function calling 变得可离线测试**（例如接入本地小模型），
   应换回原生以省掉一次解析 —— 但那要先解决"不可验证"这一条。
3. **若面试训练（`chat.py`）与有据答疑出现真实的功能重叠需求**
   （例如"答完题想追问考点"），届时再考虑合并入口，
   而不是现在为了"避免两个模块"提前合并。
4. **若正确拒答率过高**（把能答的也拒了），应检查下限闸门是否过严，
   而不是取消拒答 —— 拒答是产品承诺的一部分。
