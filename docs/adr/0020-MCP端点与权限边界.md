# MCP 端点：按当前版规范实现、只读、只暴露官方语料

## Status

accepted（2026-06-11）

> 上游：[ADR-0017](./0017-问答老师用新模块而非改造chat.md)（三个工具与 `ToolSpec` 契约）、
> [ADR-0013](./0013-官方语料命名空间隔离.md)（`Scope` 与命名空间）。
> 范围依据：`docs/改造计划.md` §3 第 10 项。

## Context

`services/tools.py` 里的 `search_kb` / `lookup_law` / `check_quote` 本来就是
「问答老师 Agent」的工具，已有 18 个用例覆盖参数校验、条号精确、权限不越界。
MCP 让它们**同时**能被任意 MCP 客户端（Claude Desktop、IDE 助手等）调用 ——
**本项不新增任何检索能力，只做协议适配。**

开工前先查规范（用 Context7 取 MCP 官方站点），结果**推翻了我原本的假设**：

| | 我原本以为 | **规范实际（2026-03-30）** |
| --- | --- | --- |
| 建立连接 | `initialize` + `notifications/initialized` 握手 | **无握手**，改为必需的 `server/discover` |
| 协议状态 | protocol-level session（`Mcp-Session-Id`） | **无状态**：每个请求自带 `_meta` |
| 流 | 独立 GET SSE 流、可续传 | **取消 GET 流**，GET / DELETE 一律 `405` |

如果我按记忆直接写，结果会是一个**自测全绿、但没有任何客户端连得上**的服务
—— 这正是"协议实现必须查规范而不能凭记忆"的原因。

## Decision

### 1. 实现当前版规范（`2026-03-30`），无状态

`server/discover` → `tools/list` → `tools/call`，每个请求的 `params._meta` 必须携带
`io.modelcontextprotocol/protocolVersion`（规范：缺失即"请求畸形"，回 `-32602`）。

无状态对我们是好事：FastAPI 端点天然无状态，不必维护会话表。

**支持的版本只有 `2026-03-30`**；其他版本回规范定义的 `-32022`，
并在 `data` 里给出 `supported` 与 `requested`。

### 2. 旧版客户端的 `initialize` 回 `-32601` —— 这是**规范行为**，不是"没实现"

规范写明：旧版客户端靠**特定错误码**判断服务端属于哪个时代，随后改用 `server/discover`。
所以 `-32601 Method not found` 正是它期待的答复；
`GET` / `DELETE` 回 `405` 同理（那是旧流式传输的入口）。

把这两条写进代码注释与测试，是为了避免后来者把它们当成"待补的兼容性缺口"而"修掉"。

### 3. 不引官方 `mcp` SDK

两个理由，第二个更主要：

1. 本环境 pip 源不可达（`mcp` 装不上）；
2. **为一个单一出口引入协议框架，会把"一处适配"变成"处处跟随它的版本节奏"** ——
   与本仓一贯取向一致（自实现 BM25 而不引 `rank_bm25`、不引 torch）。

代价必须说清楚，见下面的已知边界。

### 4. 工具清单**直接由 `tools.TOOLS` 生成**，不手写第二份

`ToolSpec.parameters` 本身就是 JSON Schema，正好就是 MCP 要的 `inputSchema`。
手写第二份的后果是双份维护：`tools.py` 改了描述，MCP 这边不跟着变，
于是「Agent 用的工具」与「MCP 客户端看到的工具」悄悄分叉。
`test_工具清单直接来自_tools_不手写第二份` 钉住这一点。

### 5. 权限：**写死 `namespace=official`**

MCP 端点**没有身份上下文** —— 面试官与桌面客户端都要能直连演示，
那里没有（也不该有）考生的登录态。所以 scope 是**一行常量**：

```python
ToolContext(db, Scope(namespace=NAMESPACE_OFFICIAL), candidate_id=None)
```

个人资料**不可能**经由此端点泄出。这不是靠调用方自觉传对参数 ——
想越权必须改这行代码。

`test_MCP端点绝不返回个人资料` 用一条**记号字符串**（`ZZQ`）做断言：
它只存在于个人资料里，一旦出现在响应中就说明越权发生了。

### 6. HTTP 层：**缺失宽容、不一致严格**

规范把 `MCP-Protocol-Version` 与 `Mcp-Method` 标为必需。本实现的取舍：

- **缺头 → 放行**（按请求体里的版本判定）。宽容缺失不会造成误判；
- **头与请求体不一致 → `400`**。不一致一定是客户端或中间代理出了问题，
  继续执行等于把一次错误的路由当成正常调用 —— 那才是真的危险。

### 7. 错误分界：业务失败走 `isError`，协议错误走 JSON-RPC error

- `params.name` 缺失 → `-32602`（请求本身不合法）；
- 工具名不认识 / 参数不合法 / 工具内部报错 → `isError: true` + 文字说明。
  规范把 `isError` 定位为「给模型可据以修正的反馈」——
  模型换一个工具或改一个参数就能继续，不必中断整个会话。

### 8. 通知回 `202`，GET / DELETE 回 `405`

通知没有 `id`，回一个 JSON-RPC 响应反而是协议错误 ——
所以先判"是不是通知"，再决定状态码。

## Considered Options

- **凭记忆按旧版握手实现**（否决）：会做出一个自测全绿、客户端连不上的服务。
- **同时支持新旧两代**（暂缓）：那要按旧版规范再实现一套会话语义；
  在没有真实客户端可验证的情况下，做两代等于把"未验证面"翻倍。
- **引官方 `mcp` SDK**（否决）：pip 不可达；且为单一出口引框架与本仓取向不符。
- **MCP 端点开放 `namespace=both` 并传 candidate_id**（否决）：
  等于把考生私人资料暴露给任何调用者。
- **缺 `_meta` 时默认按当前版本放行**（否决）：规范定为必需；
  放宽会让漏字段的客户端拿到看似正常的结果，换客户端时突然失败。
- **未知工具回 JSON-RPC error**（否决）：那样模型拿不到"可用工具列表"这条
  可据以修正的反馈。

## Consequences

- **知识库能力多了一个协议出口**：同一份实现、同一套 Schema、同一套校验，
  没有第二份工具定义，也就没有第二套漂移。
- **新增 21 个用例**（`tests/test_mcp_server.py`），三条是红线：
  `test_MCP端点绝不返回个人资料`、`test_工具清单直接来自_tools_不手写第二份`、
  `test_旧版客户端拿到的_initialize_是时代探测信号`。
- **新增端点**：`POST /mcp`（另有 `GET` / `DELETE` 回 405）。
- 全量回归 **451 passed / 10 skipped**。

### 已知边界（记为未决，不假装已完成）

1. **没有任何第三方 MCP 客户端连过本服务**（这是本项最大的弱点）。
   "符合规范"来自**按规范实现 + 自己的协议级测试**，**不是**互操作测试。
   真实客户端可能在意我们没实现的细节（`ttlMs` 的语义、能力协商的边角、
   对 `text/event-stream` 响应的期待）。**在真实客户端连上之前，
   "支持 MCP"这句话只能说到"实现了该版规范的必需方法"这一层。**
2. **只支持当前版**（`2026-03-30`）。旧版客户端会被 `-32601` / `405` 挡回
   —— 规范允许这样，但生态里多数客户端此刻仍在旧版，实际可用性未知。
3. **`Accept` 头未做校验**：规范要求客户端同时接受 `application/json` 与
   `text/event-stream`；我们只回 JSON（规范允许二选一），但没校验客户端的期望。
4. **无速率限制与鉴权**：端点公开只读，语料是公开政府公文，
   但**没有任何防滥用措施**（无限流、无 API key）。公网部署前必须补。
5. **未实现资源（resources）与提示（prompts）能力**：`capabilities` 只声明 `tools`。
6. **`ttlMs` / `cacheScope` 是照规范填的常量**，没有实测过客户端如何使用它们。

## 反转条件

1. **若 pip 源恢复**，应立刻装官方 `mcp` SDK 并用它的客户端**跑一次互操作测试**；
   若发现形状不一致，以真实客户端为准修改本实现（而不是维护自己的解释）。
2. **若出现明确需要旧版客户端的场景**，再按旧版规范实现会话语义；
   但**必须先有可验证的客户端**，否则只是把未验证面翻倍。
3. **若要把 MCP 端点暴露到公网**，必须先补鉴权与限流 ——
   当前设计假设它只在内网/本地被面试官直连。
4. **若将来要经 MCP 暴露个人资料**，那必须引入与小程序同级的身份机制
   （而不是简单地把 scope 改成 `both`）—— 那是一次独立的设计，不是改一个常量。
