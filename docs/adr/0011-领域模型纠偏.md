# 领域模型纠偏：`Subject` 由「一科一值」改为「科目序号 × 学段 → 领域包」

## Status

accepted（2026-06-10）｜ **撤销 P1 的 `Subject` 口径**（`COMPREHENSIVE` / `EDU_KNOWLEDGE` / `SUBJECT_KNOWLEDGE`）

> 触发依据：`docs/用户需求文档.md` §5 把两条偏差判为 🔴 致命 ——
> **D2** 综合素质「各学段通考」错误（实为分卷命题 101 / 201 / 301）；
> **D3** 科目二名称不分学段（实为保教 / 教育教学 / 教育知识三套不同考纲，模块数 7 / 7 / 8）。
> §6「校准后的目标排序」把「领域模型纠偏」列为**第一步**：不加题之前先把轴改对。

## Context

P1 打进库里的 `Subject` 是「一个枚举值 = 一科」：

```python
COMPREHENSIVE = "综合素质"
EDU_KNOWLEDGE = "教育知识与能力"      # ← 只有中学版本用这个名字
SUBJECT_KNOWLEDGE = "学科知识与教学能力"
```

问题不在命名，而在**指代范围**：官方口径里科目二**随学段改名**，
幼儿园《保教知识与能力》、小学《教育教学知识与能力》、中学《教育知识与能力》。
用一个 `EDU_KNOWLEDGE` 指代三者，等于把三套不同考纲（模块 7 / 7 / 8、内容完全不同）压成一套 ——
任何按科目做的统计与组卷都会把三个学段的题混在一起。

同时 `KnowledgePoint.code` 用旧 `Subject.value`（中文科目名）做前缀
（`综合素质/职业理念/教育观`），与「科目二有三个名字」的事实冲突。

## Decision

**`Subject` 改为「科目序号 × 学段」唯一确定的领域包（Domain Pack）**，枚举值 = 领域包目录名。

1. **枚举成员 = 已实现的包数**，不是官方的科目数：
   `K1_COMPREHENSIVE = "k1_comprehensive"`、`K2_MIDDLE = "k2_middle"`（本期范围见 ADR-0012 / `docs/改造计划.md` §1）。
2. **新增官方口径查表与函数**（`models.py`）：
   `SUBJECT_META`（序号 / 名称 / 覆盖学段）、`PAPER_CODES`（101 / 201 / 302…）、
   `subject_of()`、`paper_code_of()`、`OFFICIAL_SLOTS`（官方全表，含未实现）、`missing_packs()`。
3. **`KnowledgePoint.code` 前缀改为领域包名**：`k1_comprehensive/职业理念/教育观`。
   好处是前缀与 `Subject.value` 同源，**不需要任何「值 ↔ 目录 / 中文名」映射表**；
   科目二的三名称歧义由包名天然消解。
4. **`QuestionType` 补三型**：`MATERIAL`（材料分析）/ `WRITING`（写作）/ `DESIGN`（教学设计）。
   只加三型，因为它们覆盖科目一 61% 卷面；其余官方题型留到真正要批改时再加，避免长出「有题型、无 rubric」的空壳。
5. **清空存量题目与知识点树**（迁移 `c9d0e1f2a3b4`），由种子脚本重建。

### 为什么必须清空，而不是回写值

`subject` / `stage` 由 `SAEnum(native_enum=False, validate_strings=True)` 渲染，
**实测 `create_constraint=False` → 落库是 `VARCHAR(32)`，数据库侧没有任何 CHECK 约束**。
也就是说旧成员名 `COMPREHENSIVE` 能**安然躺在列里**，直到**读**的时候才由 Python 侧抛 `LookupError` ——
「能存、不能读」的延迟爆雷，排查成本极高。

且旧 `EDU_KNOWLEDGE` 覆盖三学段，**无法无歧义地回写成某一个新包**；
本期范围又砍掉了非中学科目二（ADR-0012），
把已砍科目的数据回写成「现存的科目」等于制造一批**没有领域包支撑**的题。

## Considered Options

- **保留单一 `EDU_KNOWLEDGE`，只靠 `stage` 区分**（放弃）：科目二的三套考纲模块数都不同（7 / 7 / 8），
  单靠 stage 标签无法表达「模块树不同」，覆盖度统计与组卷权重都会错。
- **三科各拆三个包（9 个包）**（放弃）：科目一全学段模块树一致（差异只在分卷命题），拆三个包是重复；
  科目三按学科细分会更爆炸。本期范围只留 2 个包（ADR-0012）。
- **只加 `stage` 维度、科目名保持中文不变**（放弃）：不解决「一个值指代三套考纲」的根本问题，
  且中文名做题前缀在科目二上必然歧义。
- **给 `subject` / `stage` 加数据库 CHECK 约束（`create_constraint=True`）**（**未采纳，记为已知代价**）：
  能在写入侧拦住非法值，但需要重建表与约束，且与「新增列一律可空」的升级期约定相互牵扯。
  当前只有 Python 侧 `validate_strings=True` 守写入 —— **数据库层不设防**。
- **清空存量（采用）**：见上文「为什么必须清空」。

## Consequences

- **数据不可恢复**：迁移删除了 `questions`（1009 行）、`knowledge_points`、`mistake_book`、`error_reports`，
  并把 `sessions.question_ids` / `doc_tasks.generated_question_ids` / `kb_tasks.generated_question_ids` 重置为 `[]`、
  `chat_turns.question_id` 置 NULL（保留对话本身）。迁移已实测：升级后无悬空引用。
- **两类枚举的迁移路径不同**，必须分方言处理：`Subject` / `Stage` 是 VARCHAR（**无需 DDL**）；
  `QuestionType` 在 PG 上是**原生 ENUM `questiontype`**，新增成员需 `ALTER TYPE ... ADD VALUE`。
  ⚠️ **PG 分支未在本机验证**（无 PG 环境），仅 SQLite 路径实测通过。
- **`Module` 枚举仍是科目一专属** —— 科目二的 8 个模块没有枚举表示，见 ADR-0012 的「已知边界」。
- **测试基线**：改后全量 `pytest` = **264 passed / 9 skipped**（`docs/项目计划书.md` 里旧写的 243 已过期）。
- 新增依赖 `pyyaml`（读 `pack.yaml`）。

## 反转条件

出现下列任一情形时重新评估：

1. 需要同时开启 3 个以上科目包，且「一个枚举成员 + 一个目录」的手工同步成为实际负担；
2. 需要**运行时**按用户配置动态启用科目（此时枚举必须让位给数据表 + 外键）；
3. 有明确的越权/脏数据事故，证明「数据库层不设防」必须补 CHECK 约束。
