# 领域包（Domain Pack）：身份在代码、内容在数据，以及四条不变量

## Status

accepted（2026-06-10）

> 上游：[ADR-0011](./0011-领域模型纠偏.md)（`Subject` 改为「科目序号 × 学段 → 领域包」）。
> 范围依据：`docs/改造计划.md` §1（决策 8b：只保留 `k1_comprehensive` + `k2_middle`）。

## Context

需要一条能持续复用的扩展方式：**加科目时不必改业务逻辑**。
但 `Subject` 是类型安全枚举，`Question.subject` 是 `SAEnum` 列（PG 上要迁移），
所以「科目完全由目录动态生成」与「静态类型 + 迁移可控」之间必须做取舍。

同时有两个具体约束：

1. **官方口径会变**（考纲修订、模块调整、分值变化），这类内容需要注释、需要 diff 可读 ——
   放代码里会变成散落各处的 if/else（旧 `EDU_KNOWLEDGE` 正是这么来的）。
2. **官方并非所有数据都公布** —— 例如科目二的模块权重（`docs/用户需求文档.md` §1.2 只给模块名）。

## Decision

**领域包 = 目录 + `pack.yaml`；加载与校验收敛在 `domain_packs/loader.py` 一处。**

### 1. 职责边界：身份在代码，内容在数据

| 内容 | 权威位置 | 理由 |
| --- | --- | --- |
| **身份**：枚举成员、科目序号、官方名称、覆盖学段、试卷代码 | `app/models.py`（`Subject` / `SUBJECT_META` / `PAPER_CODES`） | 枚举成员必须存在于代码，`Question.subject` 才能在类型与迁移上受控 |
| **内容**：模块与权重、题型、考纲版本 | `pack.yaml` | 随考纲修订而变，且**最需要写注释**（YAML 支持，JSON 不支持） |

`pack.yaml` **不重复声明身份元数据**；loader 把身份**注入**给 `Pack` 对象。
两处都写就会出现「改了其中一份、没有任何报错」的漂移。

### 2. 四条不变量（加载期即报错，不做「尽量修正」）

| # | 不变量 | 不守住的后果 |
| --- | --- | --- |
| 1 | 目录名 == `key` | `Subject.value` 与目录脱节，「枚举值即目录名」的便利失效 |
| 2 | `key` ∈ `Subject` 枚举 | 出现「有包、无科目」的幽灵包：能加载，但按 `Subject` 过滤的逻辑看不到它 |
| 3 | `question_types` 每项 ∈ `QuestionType` 成员名 | 写错一个（如 `materials`）会让组卷**静默漏掉**该题型 |
| 4 | 声明了权重的包，权重之和 == 1.0（容差 1e-3） | 组卷题量按权重分配，和不等于 1 会让卷面结构与考纲不符 |

**不变量 4 只在「所有模块都写了 `weight`」时生效**；只要有一个没写，本包整体视为未标权重，跳过校验 ——
不混合、不补默认值、不用平均值兜底。

### 3. 缺口语义：「未实现」≠「官方不存在」

`models.OFFICIAL_SLOTS` 登记官方全部 6 个「科目序号 × 学段」槽位（`docs/用户需求文档.md` §1.1），
`missing_packs()` 据此算出缺口。`subject_of()` 对「官方存在、本仓未实现」返回 `None`（而非抛错），
调用方据此提示「该科目暂未开放」。

**没有这一层，后来者会把「本仓还没做」误读成「官方没有这个科目」。**

### 4. 已知边界：`Module` 枚举是科目一专属

科目二的 8 个模块没有枚举表示，`pack.yaml` 只能声明 `name`、`enum` 留空。
`module_weights(k2_middle)` 与 `k2_middle` 未标权重时会**明确报错**，而不是静默返回空列表。

## Considered Options

- **纯数据驱动：科目由目录动态生成，不写枚举**（放弃）：丧失静态类型，
  `Question.subject` 只能退化成自由字符串，迁移与校验同时失控。
- **把科目二 8 模块并入 `Module` 枚举**（放弃）：`Module` 同时驱动「五维掌握度雷达」与组卷权重，
  并入会让科目一的五维统计混入科目二模块。
- **给科目二编一份平均权重（1/8）**（放弃）：**编造数据**。官方未公布就留空，
  让它显式报错，而不是用一个看起来合理的数字掩盖不确定性。
- **`pack.yaml` 自报身份元数据 + loader 与 `models` 交叉校验**（放弃）：
  看似「单文件自描述」，实则制造两份真相；校验只能发现问题，不能消除重复。
- **本期实现 5 个包**（放弃）：与 `docs/改造计划.md` §1 的「做精」边界冲突；
  留 `k2_middle` 的唯一目的是**证明扩展方式成立**，不是铺量。

## Consequences

- **加科目 = 加一个枚举成员 + 加一个目录**（不是「零代码」）。这是**刻意**的取舍：
  用「改一行代码」换回静态类型与迁移可控性。诚实版清单写在 `domain_packs/README.md`。
- 依赖新增 `pyyaml`；`k1_comprehensive` 的权重之和为 1.0（0.15 / 0.15 / 0.10 / 0.12 / 0.48）。
- **`k2_middle` 有两个「显式留白」**（未映射枚举、未标权重），都写进了 `pack.yaml` 的注释 ——
  留白是决策，不是遗漏，必须让人一眼看出。
- 四条不变量各有一条用例守着（`backend/tests/test_domain_packs.py`），
  用临时目录造「错的包」验证确实会被拦下。

## 反转条件

1. **科目二真正启用出题 / 统计时** —— 必须先在「扩 `Module` 枚举」与「引入包内模块标识」之间做选择：
   - 扩枚举：简单，但五维统计需要额外排除逻辑；
   - 包内标识：干净，但 `Question.module` 要从枚举列改成「包 + 模块」二元组，迁移面大。
2. **官方公布科目二模块权重时** —— 填入 `weight`，不变量 4 会自动开始生效。
3. **同时维护 3 个以上包、手工同步枚举成为负担时** —— 重新评估「身份也交给数据」。
