# 出题质量闸门 G2（事实一致性）与 G3（答案唯一性投票）

## Status

accepted（2026-06-11）

> 上游：[ADR-0014](./0014-引用校验用子串硬匹配.md)（引用硬校验）、
> [ADR-0017](./0017-问答老师用新模块而非改造chat.md)（`lookup_law` 的条号精确纪律）。
> 范围依据：`docs/改造计划.md` §3 第 8 项。

## Context

出题链路此前有两道闸：G1 结构校验（`validation.py`）与引用硬校验（`citation.py`）。
它们各自有一个**明确的盲区**，而两个盲区都会让"AI 出的题不能用"这件事**静默通过**：

### 盲区一：引用校验只看模型**主动申报**的依据

`source_quote` 是模型自己声明"我依据的是这段"。模型完全可能**不在** `source_quote` 里申报，
却把一条法条直接写进题干：

> 「根据《教师法》**第八十七条**规定，教师可以自行决定教学内容。」

这句法条若是编的，引用校验一点也拦不住 —— 因为它根本没被当作"引用"申报。

### 盲区二：已有的 LLM 自检**看着答案**评分

`_selfcheck_batch` 把题干、选项、答案、解析一起给模型，问"是否忠于资料"。
它对「**答案本身有歧义**」完全不敏感：一道模棱两可的题，答案写成哪个它都会说"对"。

## Decision

### 1. G2 事实一致性：扫**题面**而非申报，零成本硬匹配

扫 `stem` / `explanation` / 选项文本里的全部「《X》第N条」，逐条核对是否真在依据里。

**条号必须精确**（与 `tools.lookup_law` 同一条纪律）：
判据是 `heading_path` 的**最后一段恰好等于该条号** ——
`《教师法》第七十七条` 不能因为库里存在 `第七条` 就算命中。
（`第-七-十-七-条` 里不含连续子串 `第七条`，所以这条判据不会放松精度。）

- **法名允许简称**：模型写「教师法」而语料里是「中华人民共和国教师法」，这是正常现象；
- **法名必须出现**：依据里没有这条法 → 判定"引用了不存在的法条"。
  这不是误伤，而是**正确行为** —— 它说明模型用了**外部知识**，
  而那正是"AI 出的题不能用"的主要来源；
- 无 `heading_path` 的个人资料语料：退化为"正文里能同时找到法名与条号"。

**G2 默认开启**（`GATE_G2_ENABLED=true`），因为它是零成本确定性判定。

### 2. G3 答案唯一性投票：**盲答** N 次，默认关闭

**为什么必须盲答**：看到答案的评判测不出歧义（见 Context 的盲区二）。
所以 G3 只把题干与选项给模型，让它独立推导 N 次：

| 观察 | 判定 |
| --- | --- |
| N 次结果**不一致** | 题目有歧义 → 拦截 |
| N 次一致但**与题目自带答案不符** | 题目答案是错的 → 拦截（更严重） |
| N 次一致且相符 | 通过 |

**默认关闭**（`GATE_G3_ENABLED=false`，`GATE_G3_VOTES=3`）：它是 **N 倍成本**，
只在"高价值题"（如官方语料出的题）上开 —— 与计划里那条成本纪律一致：
G3 与批改一致性度量都是 3 倍开销，必须用开关控制，不能默认全开。

### 3. 四条防"误杀"的细节（都来自"闸门自己也会出错"）

1. **无效投票丢弃，不算作不一致**：模型不可用/解析失败时返回 `n=0`，调用方**放行**并记事实。
   否则一次接口抖动就会把好题成批判死、欠产飙升。
2. **多选题键序归一化**：`["B","A"]` 与 `["A","B"]` 是同一个答案，不该判为不一致。
3. **非选择题型直接放行**：简答/填空没有"唯一答案"这个概念 ——
   对它们谈唯一性是**概念错误**，不是"没通过"。
4. **替身必须能走通成功分支**：`FakeLLMClient` 的盲答按 `_fake_doc_questions`
   的字面约定挑正确选项。若它答不对，G3 会把 fake 模式下**每一道题**都拦掉，
   那条链路就再也测不到了（与出题链路的引用校验同一个道理）。

### 4. 顺序即成本顺序

```
G1 结构校验 → 引用硬校验 → G2 事实一致性 → LLM 自检 → G3 唯一性投票
   零成本        零成本         零成本         高成本      N 倍成本
```

前四道把问题砍完之后，只剩"值得花 N 倍成本"的题进 G3。

### 5. 两个分支都要过（沿用引用闸门的纪律）

`_apply_extra_gates` 在 `enable_loop=True/False` 两条路径上**都**被调用 ——
若只在 loop 路径加，编排 A/B 对照（loop vs 非 loop）就混入了第二个变量。

## Considered Options

- **不做 G2，靠引用校验**（否决）：模型不申报就绕过了，缺口是真实的。
- **G2 用 LLM judge 判事实一致性**（否决为默认）：成本高且不确定；
  法条引用是**结构化**的东西，字符串核对足够且零误判。
  （留作反转条件：非引用类的事实错误它管不了。）
- **G3 复用已有自检**（否决）：看着答案的自检对歧义不敏感 —— 那正是要测的东西。
- **G3 默认开启**（否决）：3 倍成本不该成为默认。
- **把无效投票算作不一致**（否决）：接口抖动会成批判死好题。
- **G3 覆盖全部题型**（否决）：对简答/填空谈唯一性是概念错误。

## Consequences

- **出题链路现在有五道闸**，且前四道是确定性判定（零模型调用）——
  编造与格式错误的题在花 LLM 额度之前就被砍掉。
- **G2 补上的是"未申报的引用"这个缺口**，这是引用校验（ADR-0014）结构性看不到的一类。
- **新增 21 个用例**（`tests/test_quality_gates.py`），其中两条是"红线"：
  `test_条号必须精确_第七十七条不能靠第七条蒙对`、
  `test_G3_改坏答案的题会被拦`。
- **新增 3 个配置项**：`GATE_G2_ENABLED` / `GATE_G3_ENABLED` / `GATE_G3_VOTES`。
- 全量回归 **412 passed / 10 skipped**。

### 已知边界（记为未决，不假装已完成）

1. **G2 只查「《X》第N条」形态的引用**。它管不了其他形态的事实错误
   （把法条内容说反、把两个法条的内容混起来、非条号类的专名错误）。
   那类需要 LLM judge，本项未做。
2. **G3 的成本没有实测**：本项只验证了判据与链路，没有测 N=3 时的
   延迟与 token 增量。上线前必须补 —— 它是"默认关闭"这个决定的另一半依据。
3. **G3 只在 `LLM_MODE=fake` 下验证过**。真实模型下"同一题盲答 3 次是否一致"
   这件事本身未知（真实模型可能比 fake 更不稳定，也可能更稳定）。
   因此 **G3 的拦截率在真实模型下是多少，目前无数据**。
4. **G2 的误杀风险未经真实语料检验**：若官方语料本身缺条（如考纲类语料没有条号结构），
   G2 会把合法的引用判为不存在。当前语料只有法条有 heading 结构，
   考纲类语料尚未抓取（见 ADR-0016 的已知边界）。

## 反转条件

1. **若 G3 在真实模型下的拦截率过高**（把大量好题判为有歧义），
   应先检查是不是提示词让模型"想太多"，而不是取消 G3 ——
   "题目有歧义"是真实存在的质量问题。
2. **若 G3 的实测成本超出预算**，应下调 `GATE_G3_VOTES` 或改为抽样
   （只投高价值题），而不是全量开关式地开/关。
3. **若出现非引用类的事实错误成为主要问题**，应引入 LLM judge 作为 G2 的第二段
   （硬匹配先跑、零成本先砍），而不是用 judge 替换硬匹配。
4. **若考纲类语料入库**，G2 的"法名 + 条号"判据不适用（考纲没有条号结构），
   届时需要为这类语料定义新的依据判定，而不是让 G2 空转或误杀。
