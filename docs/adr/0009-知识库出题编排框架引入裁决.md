# 知识库出题：编排框架引入裁决（修订 ADR-0008）

## Status

accepted（2026-03-22）｜ 修订 ADR-0008（在其「默认不引」总基调下，把「触发条件出现时从零引入 LangChain 检索层」细化为「已走通验证的 LangGraph 编排路线可用」）

## Context

ADR-0008 在「线性单文档出题管线」前提下裁决「暂不引入 LangChain/LangGraph」。但新增「自然语言范围跨文档出题」需求后，我们把出题链路升级为带**质量闭环**的编排（检索相关性评分→查询改写重检索；生成后自检→重生成），并据此以代码级走通 + 对比实验重新评估 LangChain/LangGraph 的引入价值。

代码级实现三条路线（`backend/app/services/kb_retrieval.py` / `kb_generate.py` / `kb_graph.py`，入口 `backend/app/routers/kb.py`）：

- 路线① baseline：现有单文档管线（对照基线，结构上无法满足跨文档需求）。
- 路线② kb_handwritten：跨文档检索 + **手写**质量闭环状态机。
- 路线③ kb_langgraph：跨文档检索 + 同一质量闭环的 **LangGraph StateGraph** 实现。

三条路线在 `backend/eval/` 评测 harness 下做受控对比实验（控制变量：共享同一检索/提示词/LLM 接缝/校验逻辑，唯一差异为编排层）。

## Decision

**采纳路线③（LangGraph StateGraph 编排）作为知识库出题的生产默认路径；路线②（手写质量闭环）保留为可显式选择的备选。** 这是用户在三路线代码级对比实验后作出的直接决策（推翻此前「路线②默认、③备用」的推荐）。

1. **当前生产默认路径 = 路线③（LangGraph 编排）**：HTTP 入口 `POST /api/kb/generate` 的 `route` 字段默认 `"graph"`，经 `_select_generator` 分发到 `kb_graph.generate_by_scope_graph`；`route="handwritten"` 仍可走路线②。
2. **路线②（手写质量闭环）保留为就绪备选**：当 LangGraph 编排在某环境/依赖受限时显式回退，且评测 harness 仍需要两套路线做受控对比。
3. **纯 LCEL/RAG chain 对本项目增益小（现有校验/分批/去重已强），不单独引入**；需要检索层能力时复用已落地的 `kb_retrieval` 混合检索 + RRF，而非引入 LangChain 的 `PGVector`/`EnsembleRetriever`。

> 越阈值优先③ 的原设想已自然满足：路线③ 现即默认，无需再「触发切换」。

## Considered Options

- **路线③ LangGraph 为默认 + 路线② 保留可选**（采用）：用户在三路线对比实验后直接决策；效果与手写等价，且 LangGraph 可扩展性更优、已代码级走通验证可用。
- **路线② 手写为默认**（原推荐，未最终采纳）：效果等价下可控性更优、零额外依赖；但用户选择以 LangGraph 为默认以获取其编排/可观测性/可扩展性优势。
- **从零引入 LangChain 检索层（PGVector/EnsembleRetriever）**（未采纳）：与现有 `document_chunks` + `candidate_id` 权限模型适配成本高、版本耦合强，且检索增强收益已被自研混合检索 + RRF 覆盖。

## Consequences

- **用户直接决策**：知识库出题生产默认走路线③（LangGraph）。`POST /api/kb/generate` 的 `route` 字段默认 `"graph"` → `_select_generator` 分发到 `kb_graph.generate_by_scope_graph`；`route="handwritten"` 仍可走路线②。
- 依赖新增 `langgraph==1.2.11` + `langchain-core==1.6.2`，已验证与 pydantic 2.9.2 / fastapi 0.115 / Python 3.11 无冲突，钉入 `requirements.txt`。
- 现有单文档出题管线（`doc_generate` / `embedding.retrieve`）一行不动，并行新增 `/api/kb/generate`，blast radius 受控。
- 质量闭环重试上限硬编码（每批 ≤1 次重检索 + ≤1 次重生成），LLM 成本约 1.5~2 倍（fake 实测每题 6 倍，因 baseline 批处理摊薄），需在真实实验中量化质量增益。
- 评测 harness 支持 fake 离线（默认）与 real 真实模式（`--real` + `EMBEDDING_MODE/LLM_MODE=real`），真实质量差异由真实实验计量，不依赖 fake 下的质量相等。

## 实验依据（摘要）

fake 离线模式（确定性伪 LLM，三路线产出均合法可解析）：路线 ②③ 五维质量均 4.0、LLM 调用数均 72、提示词字符均 38354（逐项相等，证明框架对效果中立）；baseline 因批处理摊薄为 0.5 调用/题。真实 LLM 下质量闭环捕捉的错误数即路线 ②③ 相对 baseline 的质量增益，由 real 模式计量。详见 `docs/RAG与题库技术选型方案.md` §1、§4。
