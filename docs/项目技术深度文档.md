# AI 闯关学习小程序 · 技术深度文档

> 面向「深度学习本项目」的整理文档：架构、实现、数据流、算法、设计决策与踩坑复盘。

## 0. 一句话概览

**微信原生小程序 + FastAPI + SQLAlchemy** 的 AI 出题与闯关学习产品，支持三条学习链路：官方题库闯关、上传资料跨文档 RAG 出题、AI 模拟答（聊天式追问评分）。内置审校闭环、配额限流、连胜激励与复盘统计。

- 后端 `backend/`：Python 3 + FastAPI + SQLAlchemy 2.0 + SQLite/PG + Alembic
- 前端 `miniprogram-native/`：微信原生，零 npm 运行时依赖，11 个页面
- AI：统一收口的 LLM 客户端（DeepSeek / 通义，OpenAI 兼容协议）+ Embedding + 三级降级检索

## 1. 整体架构设计

### 1.1 分层结构

```
表现层  miniprogram-native（原生页面 + utils/api.js）
        index / quest / answer / review / mistakes / history
        settings / docs / doc-detail / generate / chat-train
              │ HTTP(REST/JSON) · X-Unionid 身份头
接口层  app/routers/（14 模块 FastAPI Router）
        identity sessions review mistakes daily quota reports
        admin documents tasks streak chat health
              │
服务层  app/services/（可复用业务逻辑，不依赖 HTTP）
        llm_client(接缝B) validation proofread doc_parser
        embedding kb_retrieval doc_generate kb_generate kb_graph
        content_safety realtime streak task_pool
              │
管线层  app/pipeline/batch_generate.py（闲时批量扩池）
              │
数据层  app/models.py（唯一 schema 源）+ db.py + alembic/
        SQLite(dev/test) / PostgreSQL + pgvector(生产)
```

### 1.2 核心组件与职责

| 组件 | 位置 | 职责与关键设计 |
|---|---|---|
| 应用装配 | `app/main.py` | lifespan 内 `init_db()` 自动建表；注册 14 个 router |
| 配置 | `app/config.py` | `Settings` dataclass；手工解析 `.env` 且用 `os.environ.setdefault`（显式环境变量优先） |
| 身份 | `app/deps.py` | `get_current_candidate` 读 `X-Unionid`；游客 `guest_<uuid>` 先玩后登录 |
| **LLM 接缝** | `services/llm_client.py` | **服务层唯一 AI 出口**；`Fake/Real` 同接口，`get_llm_client()` 是唯一切换点 |
| 结构化校验 | `services/validation.py` | 按题型分派，是**所有 AI 产物的第一道闸**（不通过即弃） |
| 审校 | `services/proofread.py` | 按模块比例人工抽检（文化素养 0.3、其余 0.1）；REJECTED = 驳回即弃 |
| 检索 | `embedding.py` / `kb_retrieval.py` | 单文档 vs 跨文档两套；PG 走 SQL 向量、SQLite 走内存 numpy，均带降级 |
| 异步任务 | `documents.py` + `task_pool.py` | 独立 Session + 有界线程池，**GEN/EMBED 分池防死锁** |
| 数据模型 | `app/models.py` | 唯一 schema 源；`OFFICIAL_MODULES` 守住「个人资料不串官方统计」红线 |

### 1.3 领域术语（代码与文档必须一致）

- **模块 Module**：官方考纲五维 + `PERSONAL`（个人资料）。任何官方统计遍历 `OFFICIAL_MODULES`，**绝不遍历 `Module` 全部值**。
- **考点 Knowledge Point**：可独立考查的最小单元，每题归属且仅归属一个。
- **变式题 / 原题**：本项目**不存储、不展示原题原文**，题库主体是 AI 变式题。
- **切片 Chunk**：检索与喂模型的最小单位；**溯源 source_chunk** 存切片 id 清单。
- **每日额度（作答题量）** 与 **实时生成额度（LLM 调用次数）** 是两套独立限速。

## 2. 数据模型设计

### 2.1 核心表

| 表 | 关键字段 | 设计要点 |
|---|---|---|
| `candidates` | `unionid`(唯一)、`is_guest`、`exam_date` | 游客与微信登录同表 |
| `questions` | `module`、`knowledge_point`、`stem`、`options/answer`(JSON)、`type`、`source`、`proofread_status`、**`owner_candidate_id`**、**`source_chunk`** | `owner_candidate_id IS NULL`=官方池；非 NULL=个人题仅本人可见 |
| `sessions` | `question_ids`(JSON)、`result_json`、`mode`(normal/mock)、`deadline_at` | `result_json` 兼作**交卷幂等缓存** |
| `mistake_book` | `candidate_id+question_id` 唯一、`wrong_count` | 按考点聚合；**答对即删除该条** |
| `mastery` | `candidate_id+module` 唯一、`score` | EMA 更新 |
| `documents` / `document_chunks` | `storage_path`（**A3 不存原文**）、`heading_path`、`embedding`、`embed_status` | embedding 列用 `with_variant` 兼容双库 |
| `doc_tasks` / `kb_tasks` | `cancel_requested`、`request_json`、`generated_question_ids` | 进度落库，重启不丢；`request_json` 是续做依据 |
| `*_task_events` | `seq`(自增游标)、`type`、`text` | 前端 `?since=N` 增量拉，渲染出题时间线 |
| `streaks` / `streak_makeups` | `current/max/last_date/cards`；`candidate_id+missed_date` 唯一 | 补签幂等；发卡里程碑借此表记 `milestone-{n}` |
| `chat_sessions` / `chat_turns` | `persona`(coach/examiner)、`turn_type`(opening/ask/probe/hint/feedback/user)、`score`、`points_hit/missed/wrong` | ask 轮的评分要点**复用 `points_hit` 列**（避免加列迁移） |

### 2.2 三条建模巧思

1. **一字段表达多重语义**：`owner_candidate_id` 为 NULL 即官方池、人人可用；非 NULL 即个人题、仅本人。抽题一句 SQL `(owner_candidate_id IS NULL) OR (owner_candidate_id == c.id)` 同时完成「官方可见 + 个人隔离 + 越权防护」。
2. **事件表用自增 seq 做游标**：前端按 `WHERE seq > ?` 增量拉取，天然支持断线续传与打字机渲染。
3. **`result_json` 兼幂等缓存**：重复提交返回同一结果，避免网络重试造成掌握度重复累加。

## 3. 功能模块实现

### 3.1 开局与抽题（`routers/sessions.py`）

| 分支 | 条件 | 行为 |
|---|---|---|
| 个人题库局 | `doc_id` | 只抽本人该资料生成的题，不计每日额度 |
| 模考局 | `mode=mock` | 按卷面权重抽题 + 限时 |
| 官方/重练局 | `module` 或 `knowledge_point` | 从池抽题 |

- **避免相邻同题型**：`_arrange()` shuffle 后取前 n，单趟扫描，相邻题型相同则从后方找第一个不同题型交换。
- **模考权重**：`MOCK_WEIGHTS`（职业理念 15 / 职业道德 15 / 教育法律法规 10 / 文化素养 12 / 基本能力 48），逐模块 `need = max(1, round(n*w/100))`，不足从全池补齐再 shuffle。
- **量不足降级而非 409**：按实际数量开局，额度也按实际题数校验。

### 3.2 判分（按题型分派）

- 单选/多选：集合比较；多选输出**四态**（correct_selected / missed / wrong_selected / wrong_not_selected），前端区分「漏选」与「选错」。
- 填空：`normalize_answer()` 归一化（全角转半角、去空白、去句末标点、小写）后集合匹配。
- 简答：`state="self_review"`，**不计掌握度、不进错题本、不计正确率分母**（避免无意义统计污染）。

### 3.3 掌握度与复盘

- 掌握度 **EMA**：`score = round(score*0.7 + correct*0.3, 4)`（α=0.3）。
- 复盘**按局类型切换口径**：
  - 个人题库局 → 资料掌握度：按本局考点聚合，掌握度 = 该考点本局正确率，薄弱点取升序 top3。
  - 官方局 → 五维掌握度 + 错题本 `wrong_count` 降序 top3（inner join 且排除 PERSONAL）。
- 复盘段落：实时额度未满时用 LLM 覆盖模板，**成功才计数**；输出过内容安全检测，不通过即替换占位。

### 3.4 错题本与变式

- 按考点聚合；**答对即删除该条**。
- 变式题：同考点备用题优先，**池空才实时生成**（实时额度每日 3 次，超限降级纯池化）。

### 3.5 每日任务 / 连胜

- 每日任务用 `done_ids` 记录真做过的题，**「没做题直接点完成」不成立**；12h 时限。
- 连胜 `services/streak.py` 是**纯逻辑不碰 DB**：`advance()` 同日幂等、`makeup()` 四道校验、`grant_cards()` 上限 3、里程碑 3/7/14 发卡。纯函数化故可被单测直接覆盖。

### 3.6 资料出题（RAG 三条路线）

| 路线 | 编排 |
|---|---|
| ① 单文档（`doc_generate.py`） | 自写批处理 + 章节配额 |
| ② 跨文档手写闭环（`kb_generate.py`） | 检索→评分→改写→生成→自检 |
| ③ LangGraph（`kb_graph.py`） | StateGraph：`retrieve→grade→(rewrite→retrieve)→assemble→generate` |

- **解析切分**：`clean_text()` 去页眉页脚/页码/合并断行 → `split_chunks()` 按标题切段 + 滑窗（1500/200）。
- **向量化**：后台任务写 embedding，失败仅置 `embed_status=failed`，**不阻塞上传**。
- **出题前** `wait_embed_ready()` 轮询（0.5s/次，`db.rollback()` 刷新快照），20s 超时也继续。

### 3.7 AI 模拟答（`routers/chat.py`）

- **纯 LLM 生成路线**：`chat_pack` 现场出情境化面试题 + 3-4 个评分要点，带 `avoid`（已问话题）防重复。
- **评分链**：`chat_grade` 返回三态 `off_topic / need_probe / final`；**提示与追问共享补充轮次上限 2**，达上限强制终评（防离题死循环）。
- **多会话**：多场并存、可继续、可删除；`chat_turns` 全量重放支持切后台恢复。
- **绝不 fail-open**：评分失败 → 503 且不落任何 turn。

## 4. 关键算法与数据流程

### 4.1 章节配额（最大余数法）

```python
base = total // len(sections)                 # 先均分
for s in sorted(sections, key=char_count, reverse=True)[:remainder]:
    s.quota += 1                              # 余数按段长降序补给最长的段
```

段内题型分配同样用最大余数法而非各自 `round()`——踩坑记录：各自 round 会让每段每题型都算出 0，导致整卷 0 题。最后做**取整损耗校正**：`deficit = 用户选题数 - grand_total`，轮流均摊到各批次。

### 4.2 三级检索降级

```
向量检索 ──失败/为空──▶ 关键词检索(中文二元组) ──为空──▶ 均匀采样兜底
```

跨文档用 **RRF 融合**（k=60）+ `heading_bonus`（章节标题命中加权，上限 0.5）。双库分发：

- **PG**：`1 - (embedding <=> CAST(:q AS vector))` 余弦，走 HNSW。必须写 `CAST(:q AS vector)` 而非 `:q::vector`（SQLAlchemy 会把 `::` 当转义符）。
- **SQLite/dev**：内存 numpy 矩阵余弦 + 关键词 + RRF。

### 4.3 题干判重（3-gram Jaccard）

```python
def _grams(s, n=3): return {s[i:i+n] for i in range(len(s)-n+1)}
sim = len(a & b) / len(a | b)
```

- 精确层：`normalize_stem()` 命中已生成集合即弃。
- 近似层：与**最近 300 条**已落库题干比对。
- **阈值分路线**：路线①（章节配额下同模板题干天然相似）`0.85`，路线②③ `0.6`；`fake` 模式整体跳过（伪题相似度约 0.8 会误杀）。

### 4.4 批处理与补偿（不欠产）

1. 按 `doc_batch_size=3` 切批（从 6 下调：实测一次要 6 题模型常只输出 3 题）。
2. 主循环后补偿：每轮**多生成候选**（`want = min(batch*2, max(need*2,2))`）再按 `limit=need` 截断落库（不超产 + 提高命中率）。
3. 仍不足则**放宽阈值到 0.95** 再补一轮：宁可题干略相近，也不欠产。

### 4.5 协作式取消

`should_stop()` **只在批次之间**调用，返回 True 即 break——已落库题目作为**部分卷**返回。取消是「秒响应 + 保留成果」。
⚠️ 红线：`_cancelled` 检查**不能 rollback**（会把未提交的已生成题目一起丢掉）。

### 4.6 自检与降级哲学

- LLM 自检**抽检优先**（`sample=2`，均匀取样覆盖首尾），发现问题才升级全批检。
- 自检全否时**仍保留规则校验通过项**——自检不得成为欠产原因。
- 降粒度重试：粒度序列 `3→2→1`。

### 4.7 离线题库生成管线（`scripts/gen_question_bank.py`）

```
遍历考点 → LLM 出题 → LLM 逐题审校 → 通过即实时落盘 JSON → 下一考点
```

- **实时落盘**：每考点完成即写，崩溃不丢进度。
- **断点续跑**：重跑时按已完成考点集合排除。
- **网络加固**：LLM 调用包 2/4/8s 指数退避重试 ×3；考点级兜底——重试耗尽只跳过该考点记 0 题继续，**绝不因单点网络抖动杀死整条挂机管线**。
- 成果：418 题、150 考点 100% 覆盖、REJECT 率 12%（低于 30% 熔断线），替换了官方池 300 条占位假题。

### 4.8 AI 模拟答评分链

```
用户回答 → chat_grade(LLM) ─┬─ off_topic 且轮次<2 → hint 轮（也占轮次）
                            ├─ need_probe 且轮次<2 → probe 轮
                            └─ final → 终评 score=要点覆盖率
                                     → 增量更新 score_avg
                                     → 落 feedback(hit/missed/wrong/suggestion)
                                     → 立即生成下一题（无限问答）
```

## 6. 设计巧思与技术难点

### 6.1 接缝设计：LLM 可替换且可离线测试

`LLMClient` ABC + `get_llm_client()` 唯一切换点；`FakeLLMClient` 对每种 `kind` 返回确定性产物（`_fake_doc_questions` 用全局自增下标保证伪题不重复），使**全链路测试零额度**。这是本项目最重要的可测试性设计：AI 的不确定性被收口到一个接口之后。

### 6.2 Fail-open / Fail-close 边界（反复权衡的红线）

| 场景 | 策略 | 理由 |
|---|---|---|
| Chat 评分失败 | **Fail-close**：503 + 不落 turn | 静默给分会污染训练数据并误导用户 |
| 内容安全输出检测 | **Fail-close**：不通过即换占位 | 合规硬要求 |
| Embedding 失败 | **Fail-open**：仅标记继续 | 不阻塞上传，检索可降级 |
| LLM 自检不可用 | **Fail-open**：保留规则通过项 | 自检不得成为欠产原因 |
| 检索降级 | **Fail-open**：向量→关键词→均匀采样 | 宁可质量下降也不能出不了题 |
| 事件写入失败 | 静默回滚，但**取消信号必须传播** | 过程数据可丢，用户指令不可丢 |

### 6.3 时区：反复踩坑的点

SQLite 下按「本地日」统计（额度/连胜/实时额度）不能直接用 SQL 日期函数（UTC 存储偏差）。统一到 **Python 侧按服务器本地时区比对**：`created_at.astimezone().date() == local_day()`，`utils.local_day()` 是唯一入口。

### 6.4 个人资料维度的全局隔离

`Module.PERSONAL` 不参与任何官方统计。复盘雷达、掌握度、薄弱排序、额度统计都显式用 `OFFICIAL_MODULES` 而非遍历 `Module`——用常量 + 注释双保险守住这条易被迭代破坏的红线。

### 6.5 分池防死锁

`GEN` 与 `EMBED` 两个独立线程池。出题 worker 会等 embedding 完成，若共用有界池，embedding 占满后出题任务永远等不到资源 → **死锁**。分池是正确性要求而非性能优化。

### 6.6 零表迁移的功能演进

纯 LLM 路线需要随题存评分要点，但 `chat_turns` 已存在且项目用 `create_all`（不 ALTER）。方案：复用 ask 轮的 `points_hit` 列存 key_points，配注释守住约定，避免一次 schema 变更。

### 6.7 前端高频踩坑（已在代码注释固化）

| 问题 | 根因 | 解法 |
|---|---|---|
| 聊天无法滚到底 | `.page` 用 `min-height:100vh` → flex 子项按内容撑开，scroll-view **不产生内部滚动**，底部被输入栏遮住 | 父级 `height:100vh` + 子项 `min-height:0` + 底部留白 |
| `scroll-into-view` 无效 | 锚点 id **双前缀**；且同值不触发重滚 | 固定双锚点 a/b **交替**触发 |
| 一次回答两条气泡 | `onSend` 手动 push + `_reply` 默认 `local=true` 又 push | 统一由 `_reply` 内部 push |
| 答一轮后发送失效 | 防连点条件引用**从未赋值的字段**，恒真 | 实例同步锁 `this._sending` |
| 白屏 `module "app.js" is not defined` | `project.config.json` 的 `es6:false` 关闭 ES6→ES5 转换，而源码全是 ESM | 开启 ES6 转换 |
| placeholder 只显示一半 | input 无显式行高 | 显式 `line-height` |
| 长输入挤占相邻按钮 | flex 子项缺 `min-width:0` | 加 `min-width:0` + 按钮 `flex-shrink:0` |

### 6.8 提示词工程：真人感 vs 可控性

1. **禁止试卷腔**：明确要求「像真人面试官临场想到的问题」并给反例。
2. **追问必须引用用户原话**：「你说 XXX，这个方向我认，可它现在还只是个态度，不是做法」——对真人感提升最大。
3. **收紧追问条件**：初版答得完整也被追问，改为「触及 ≥1 个要点就必须直接评分」。
4. **给 LLM 兜底出口**：离题达上限必须 `final`，否则用户陷入无限提示。

## 8. 可继续深入的方向

- **流式输出**：当前 LLM 调用是同步整段返回，前端用打字机模拟；可升级为 SSE/分块流式降低首字延迟。
- **题库质量闭环**：`batch_generate` 已能闲时扩池，可结合考点覆盖度与 REJECT 率做自适应调度。
- **PG 生产化**：`with_variant` 已就绪，切换 `DATABASE_URL` 即可启用 pgvector + HNSW。
- **Chat 缓存**：纯生成路线目前不缓存题目（deepseek-flash 成本低），若换昂贵模型可加 `gen_key` 去重缓存。
