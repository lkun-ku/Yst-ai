# 提交历史

> 本文件记录仓库每一次提交的**时间、内容与影响范围**，便于后续追溯。
> **权威记录以 `git log` 为准**，本文件是人工可读的索引，每次提交后同步更新。
> 时间均为本机时区。

## 查看方式

```bash
git --no-pager log --oneline              # 全部提交（一行一条）
git show <hash>                            # 某次提交改了什么
git log --follow -p -- <文件路径>          # 某个文件的完整演变
git log --graph --oneline --all            # 图形化分支历史
git log --pretty=format:"%h|%ad|%s" --date=format:"%Y-%m-%d %H:%M:%S"   # 带时间的简洁列表
```

## 提交规范

采用 Conventional Commits，格式：`<类型>: <简短描述>`

| 类型 | 用途 |
| --- | --- |
| `docs` | 文档新增或修改 |
| `feat` | 新功能 |
| `fix` | 缺陷修复 |
| `refactor` | 重构（不改变外部行为） |
| `chore` | 工程配置、依赖、仓库约定 |

## 维护约定

1. 每次提交后，在「提交记录」表格顶部插入新行，并在下方追加对应详情条目。
2. 条目必须包含：**时间、类型、变更文件、变更内容**（说清楚「为什么改」而非只写「改了什么」）。
3. 涉及决策的变更，同步在 `docs/adr/` 中记录；本文件只做索引，不重复决策论证。
4. 本文件自身的历史条目可能滞后一次提交（先提交、后补记），完整记录请以 `git log` 为准。
