# `docs/eval/` —— 基准快照与「承诺 ↔ 证据」索引

> **分工**：`backend/eval/results/` 放**原始产物**（每次跑就新增/覆盖，含运行时间与参数）；
> 本目录放**需要长期对照的基准**，以及这份**索引**。
>
> 索引为什么必要：§6 的承诺表写的是「目标」，而数字散在十几个证据文件里 ——
> **没有索引，"某条承诺到底达标没有"只能靠人去翻**，于是很容易一直停在"应该没问题"。

📌 **本文件不写任何实测数字**（除目标值本身）。数字与判定**只在**自动生成的
`backend/eval/results/promise_report.md` 里。曾经这里也抄了一份表，于是变成
**两处维护、迟早不一致** —— 而"两处说法不同"正是本仓反复踩的那类问题。
`tests/test_eval_docs_no_drift.py` 会挡住把数字抄回来。

## 一条命令产出数字

```bash
cd backend && python eval/promise_report.py          # 读既有证据 +（fake 时）现场跑唯一性通过率
python eval/promise_report.py --live-gate            # real 模式下也现场跑（花 N 倍调用）
```

报告里每行带**证据文件与生成时间**（过期与否一眼可见）、**判定**、以及**来源类型**：

- **硬机制**（引用子串校验 / 闸门判定 / `max(k) < 语料规模` 这类不变量）→ 可复现、零误判；
- **LLM judge**（faithfulness / 评分一致性）→ 是「模型说的」，**低一档**。

> 把来源写进表里不是装饰：本轮修掉的三处口径错位，全都是因为"两种来源混在一张表里、
> 读数的人把它们当同等硬"。

## 承诺 ↔ 证据：**只看哪个文件、以及读的时候要注意什么**

| §6.3 指标 | 目标 | 证据文件 | 读的时候注意 |
| --- | --- | --- | --- |
| Recall@K | ≥ 0.80 @5 | `retrieval_baseline_官方法条.json`（415 片）、`retrieval_baseline_教资.json`（6 片） | K 由 `metrics.pick_ks(语料规模)` 决定；**小语料上远端 k 恒为满分、没有信息量**，所以别拿 6 片语料的数说话 |
| MRR | ≥ 0.60 | 同上 | 看**生产档**那一行；精排档另算一档，而**精排默认关闭** —— 达标与否取决于开不开它 |
| 引用首次通过率 | ≥ 0.90 | `teacher_baseline.json` | 硬机制（子串校验）；**可答样本很小**，证据自带 caveat |
| 拒答率 | 10% ~ 25% | `teacher_baseline.json` | 不可答集是**人工设计**的，不等于真实分布 |
| 事实性 faithfulness | ≥ 0.90 | `backend/eval/results/faithfulness.json`（由 `eval/faithfulness_eval.py` 产出） | 口径在 `metrics.faithfulness_rate`；来源是 LLM judge，**不是硬机制**，别当零误判。⚠️ 样本由语料编号类问法程序化生成、量小 —— 它证的是「链路通 + 当前模型下的达标率」，**不是**普遍事实性；拒答样本**不计入**（拒答是"没内容可判"，另有拒答率承诺） |
| 唯一性通过率 | ≥ 0.90 | **无证据文件，因为它由 `promise_report.py` 现场跑**（`--live-gate`），读数只记在报告里 —— 别读成"证据缺失" | 口径在 `metrics.evaluate_gate_pass`；**不要拿误杀率顶替** —— 两者分母不同（好题 vs 待过闸门全部） |
| 评分一致性 | 一致率 ≥ 0.80；维度标准差 ≤ 10 | `marking_baseline.json` | 两个口径**都过**才算达标；来源是 LLM judge；且**换了批改依据后不可与旧数字直接比** |
| 成本（调用次数） | 平均 ≤ 2、P95 ≤ 4 | `teacher_baseline.json` | 均值有记录，**P95 没有** —— 均值达标不代表尾部安全 |

顺带可看的（不属 §6.3，但常被一起引用）：`citation_baseline*.json`（引用闸门的成对指标）、
`g3_*_baseline.json` 与 `g3_n2_*` / `g3_n3_*`（唯一性表决的**误杀率与负样本拦截率**，
注意它们**不是**上表那个"通过率"）。

## §6.2 产品指标：**能力口径**（不是评测读数）

| 指标 | 目标 | 口径 |
| --- | --- | --- |
| 卷面覆盖率 | ≥ 95% | 按 `§1.3.4` 分值表**推算**（科目一 = 单选 + 材料分析 + 写作）；**是推算值，不是实测** |
| 主观题批改完成率 | ≥ 95% | 链路已落地（`routers/marking.py`：分项批改 + 一致性度量），**未做线上统计** |
| 北极星 / 次周留存 / 诊断命中率 | — | **未上线，无数据** —— 不要拿"链路已实现"当"指标已达标" |

## 三条读数的纪律（踩出来的）

1. **换了输入，旧基线就不再是基线** —— 批改依据从"纯官方语料"改成"答案库（同题型）优先 + 官方兜底"之后，
   `marking_baseline.json` 里的数字**不能与新数字直接比较**，需在新依据下重测（等 LLM 额度恢复）。
2. **样本变厚，结论可能翻转** —— 评分一致性的旧基线（2 道合成题）是"达标"，扩到 7 题后变"未达标"。
   「达标」这两个字在 n=2 上没有意义。
3. **"测了"不等于"测的是那条指标"** —— 上表"唯一性通过率"那一行就是例子：有一堆 G3 证据，
   但它们测的是误杀率 / 拦截率，**没有一条**是"生成题目通过 G3 的比例"。指标名与测量口径必须逐字对上。
