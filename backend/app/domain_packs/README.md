# 领域包（Domain Pack）

> **一句话**：把「科目 × 学段」的差异表达为**数据** —— 模块 / 权重 / 题型 / 考纲版本全在 `pack.yaml`，
> 加科目时**不需要改这些逻辑**。背景见 `docs/改造计划.md` §1，架构决策见 `docs/adr/0012-domain-pack结构.md`。

---

## 目录约定

```
domain_packs/
├── loader.py            # 加载 + 四条不变量校验（唯一入口）
├── README.md            # 本文
├── k1_comprehensive/    # 科目一·综合素质（覆盖幼 / 小 / 中三个学段）
│   ├── pack.yaml        # 唯一必需文件
│   ├── syllabus/        # 官方考纲 Markdown（后续由语料抓取填充）
│   ├── rubrics/         # 材料分析 / 写作 的评分标准（rubric-grounded 批改的依据）
│   └── prompts/         # 本包专属提示词（默认继承通用提示词）
└── k2_middle/           # 科目二·中学·教育知识与能力
    └── pack.yaml
```

**目录名必须等于 `pack.yaml` 的 `key`，而 `key` 必须是 `models.Subject` 的枚举值。**
这样 `Subject.value` 可直接当目录名用，不必维护「值 ↔ 目录」映射表。

## 职责边界（为什么 `pack.yaml` 里没有科目序号 / 学段 / 试卷代码）

| 内容 | 权威位置 | 理由 |
| --- | --- | --- |
| **身份**：枚举成员、科目序号、官方名称、覆盖学段、试卷代码 | `app/models.py`（`Subject` / `SUBJECT_META` / `PAPER_CODES`） | 枚举成员必须存在于代码：`Question.subject` 是 `SAEnum` 列，PG 上还要迁移 |
| **内容**：模块与权重、题型、考纲版本 | `pack.yaml` | 随考纲修订而变，且**最需要写注释**（YAML 支持，JSON 不支持） |

两处都写就会出现「改了其中一份、没有任何报错」的漂移。因此 loader 把身份元数据**注入**给 `Pack`，
而不是从 YAML 读 —— 单一真相。

## 四条不变量（loader 启动期校验，不满足即抛 `DomainPackError`）

| # | 不变量 | 为什么 |
| --- | --- | --- |
| 1 | 目录名 == `pack.yaml` 的 `key` | 否则 `Subject.value` 与目录脱节，「枚举值即目录名」这条便利失效 |
| 2 | `key` ∈ `Subject` 枚举 | 否则出现「有包、无科目」的幽灵包：目录能加载，但按 `Subject` 过滤的逻辑看不到它 |
| 3 | `question_types` 每项 ∈ `QuestionType` 成员名 | 写错一个（如 `materials`）会让组卷**静默漏掉**该题型 |
| 4 | **声明了权重**的包，模块权重之和 == 1.0（容差 1e-3） | 权重用于组卷题量分配，和不等于 1 会让卷面结构与考纲不符 |

**校验的目的是「配置错立刻可见」**，因此不做「尽量修正」、不补默认值。
不变量 4 只作用于「所有模块都写了 `weight`」的包；只要有一个没写，本包即整体视为未标权重
（官方未公布的情形），跳过求和 —— 不混合、不用平均值兜底。

## 已知边界（两条，均由 `k2_middle` 暴露，见 ADR-0012）

1. **`Module` 枚举是科目一专属。** 科目二的 8 个模块尚未进入该枚举，`pack.yaml` 只能声明 `name`。
   原因：`Module` 同时驱动五维掌握度雷达与组卷权重，并入会污染科目一的统计口径。
   后果：`module_weights(k2_middle)` **明确报错**，而不是静默返回空列表。
2. **科目二模块权重官方未公布**（§1.2 只给模块名），本包**不声明 `weight`** —— 不猜、不用平均值兜底。

## 加一个科目要做什么

诚实版清单 —— **需要改一处代码 + 加一个目录**：

1. `models.Subject` 加一个枚举成员，值 = 新目录名；
2. `models.SUBJECT_META` / `PAPER_CODES` 登记官方口径（科目序号、名称、学段、试卷代码）；
3. 新建 `<key>/pack.yaml`（`key` / `version` / `modules` / `question_types`）；
4. 补本包的知识点树种子，及可选的 `syllabus/` `rubrics/` `prompts/`；
5. 跑 `pytest` —— 四条不变量会在导入期就报出配置错误。

> **为什么不做到「纯加目录、零代码」**：`Subject` 是类型安全枚举，且 `Question.subject` 是
> `SAEnum` 列（PG 上有原生/约束两种落库方式）。让科目完全由目录动态生成，就要放弃
> 静态类型与迁移可控性 —— 这是**刻意**的取舍，不是遗漏。

## 官方槽位与缺口

`models.OFFICIAL_SLOTS` 登记官方全部 6 个「科目序号 × 学段」槽位（含未实现），
`missing_packs()` 据此报告缺口。**「未实现」与「官方不存在」是两件不同的事** ——
不要因为本仓没做就把它当成不存在。
