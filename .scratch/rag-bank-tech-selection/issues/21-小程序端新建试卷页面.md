## What to build

RAG 跨文档出题（`/api/kb/*`）后端已完整，但**小程序端完全没有入口**（此前 0 处 `/api/kb` 调用；
`docs` 页是资料管理、`generate` 页是单文档出题）。用户要求以「**新建试卷**」为概念：

- **不按单/多文档划分**，一份试卷可来自不同资料提供的不同试题
- **上传文档作为出题范围**（资料上传复用已有的「我的资料」页）
- **用户自主决定要求**：侧重哪一部分（focus）、题型（spec）——**用户决定后再出相应题型**
- **AI 出题并整理成用户使用的试题卷**

页面流程（单页完成）：
1. 试卷名称
2. 出题范围（scope 文本，跨全部已上传资料检索）
3. 题型与数量（单选/多选/判断/填空/简答，各自 +/−，为 0 不出）
4. 难度（简单/中等/较难）
5. 侧重要求（选填 focus）
6. 「AI 出题」→ `POST /api/kb/generate`（route=graph）→ 轮询 `GET /api/kb/task/{id}`
   → `GET /api/kb/task/{id}/questions` 展示试题卷

### 实现要点
- 提交时只把 `count > 0` 的题型放进 `spec`，避免后端生成空题型。
- `options` / `answer` 接口返回的是 **JSON 字符串**（`QuestionOut` 用 str 字段），
  必须 `JSON.parse` 后才能渲染（否则会按字符逐个渲染）。
- `source_chunk` 自工单 17 起为**切片 id 清单 JSON**；W-6 起为逐题精确的单 id 清单。
  前端兼容两种：解析成数组渲染 `#N`，解析失败则按早期纯文本截断显示。
- 轮询用 `setInterval` 2s，`onUnload` / `onHide` 清理定时器，避免泄漏。
- 网络抖动时轮询不终止（catch 忽略），仅在 `done`/`failed` 时停止。
