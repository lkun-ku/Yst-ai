## What to build

核心需求「**用户上传资料，AI 按照资料、再根据用户输入的要求出题**」此前只在临时脚本里手动验证过一次，
**没有回归保障**——后续改动可能悄悄破坏这条链路而不被发现（工单 18 已证明此类问题真实存在：
迁移链非幂等、PG 分支绑定参数丢失，都是测试从不覆盖的角落）。

新增端到端回归测试，覆盖完整链路：

1. `POST /api/documents` 上传资料（解析 + 切分）
2. 等待切片向量化完成（`embed_status=ok`，且 embedding 为真实 1024 维）
3. `POST /api/kb/generate` 携带用户要求（scope / spec / difficulty / focus），默认走路线③
4. 轮询 `GET /api/kb/task/{id}` 至 `done`
5. `GET /api/kb/task/{id}/questions` 交付
6. 断言：题数/题型符合 spec、选项与答案合法、有解析、**有 source_chunk 溯源**

## 设计约束

- **默认跳过**：需真实 LLM/Embedding，有费用且耗时（约 1~2 分钟）。
  显式开启：`RUN_REAL_E2E=1 LLM_API_KEY=sk-xxx python -m pytest tests/test_e2e_kb_real.py -v`
- **不硬编码密钥**：从 `LLM_API_KEY` / `DASHSCOPE_API_KEY` 环境变量读取。
- **断言稳健**：不断言 LLM 的具体措辞（有随机性），只断言结构（题数、题型、选项数、
  答案在 A~D 内、解析非空、溯源非空）与流程状态。
- **不污染默认测试**：默认 skip，不影响 `pytest` 全量运行时间与费用。

### 设计要点（避免踩坑）

- **断言只校验结构，不校验 LLM 具体措辞**：两次运行答案分别为 `C/C/C` 与 `B/C/D`，
  LLM 输出有随机性。断言题数、题型、选项数、答案在 A~D 内、解析非空、`source_chunk` 非空，
  以及资料关键词「光反应/暗反应」出现在题干或解析中（忠于资料的弱校验）。
- **`options` / `answer` 是 JSON 字符串**（`QuestionOut` 用的是 `str` 字段），
  断言前必须 `json.loads`，否则 `len()` 得到的是字符串长度（曾误判为 197）。
- **默认 skip**：需 `RUN_REAL_E2E=1` + `LLM_API_KEY`，避免每次全量跑都产生费用。
- 密钥从环境变量读取，**不入库**。

开启方式：
```bash
RUN_REAL_E2E=1 LLM_API_KEY=sk-xxx python -m pytest tests/test_e2e_kb_real.py -v -s
```
