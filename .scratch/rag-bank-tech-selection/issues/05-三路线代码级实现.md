## What to build

让知识库出题具备三条可切换的实现路径，且**唯一差异在编排层**，以便后续实验只测量"框架 vs 手写编排"本身：

- (a) **基线（对照）**：现有单文档内存检索出题管线保持不动，作为跨文档合成能力的结构对照。
- (b) **手写质量闭环（路线②）**：检索相关性评分 → 不达标则范围改写重检索；生成后自检 → 不合格则重生成，带重试上限（每批 ≤1 重检索 + ≤1 重生成）与降级兜底。
- (c) **LangGraph 编排（路线③）**：用 `StateGraph` 表达同一闭环（retrieve → grade → rewrite → assemble → generate），节点直接调用 `LLMClient`，LLM 返回 None 时各子步骤自行降级、图整体不阻塞出题。

三者共用跨文档混合检索（向量 + 关键词 RRF 融合 + 相关性评分）、四块提示词（范围改写 / 评分 / 出题 / 自检）、LLM·Embedding 接缝与结构化校验落库，无重复新增业务分支。
